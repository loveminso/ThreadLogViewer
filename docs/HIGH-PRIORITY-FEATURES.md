# ThreadLog Viewer 높은 우선순위 기능 상세 설계

작성일: 2026-10-03 · 최초 설계: v0.3.0 · 구현: v0.4.0

사용자 승인으로 아래 11개 첫 범위를 구현했다. 아래 상세 제안은 설계 근거로 남기며 실제 타입·정책은 다음 구현 상태와 [테스트 방법](FEATURE-TEST-GUIDE.md), [검증 기록](VALIDATION-v0.4.md)을 따른다.

| 범위 | 실제 연결 |
|---|---|
| 1·2·3·8·9 | `MainWindow.Navigation.cs`, `BookmarkState`, `SelectionMetrics`, `SelectionSourceRanges`, `LogProjection`의 원본/표시 매핑, `LogContext` |

| 11 | `LogTimeAnalysis` · 소유 헤더 ticks, A/B 지정·교환·이동·복사 |

문서 식별은 성공적으로 열린 불변 `LogData` 인스턴스이며 최신 작업과 투영 참조를 확인한다. Ctrl+G 숨김은 명시적 문맥 버튼을 제공한다. 숨긴 북마크·검색 결과·A/B 위치는 ‘문맥에서 열기’로 표시하고 선택하면 문맥을 연다. 앞뒤 기본값 20건, 입력 범위 0~10,000건이다. 필터 상태와 복귀 앵커는 문맥 전환 시 보존한다.

정규식의 Multiline/Singleline 기본값은 꺼져 있고 `(?m)`/`(?s)`로 지정한다. 기록별 250ms 제한과 최대 100,000개 결과가 있다. 0길이 일치는 목록에 남고 caret만 이동한다. CRLF 내부에 걸친 일치는 원본 오프셋을 유지하지만 편집기의 선택은 개행 경계로 정규화될 수 있다. 여러 강조 규칙은 목록 앞 규칙이 위에 그려지며 검색 강조가 마지막이다.

표시 설정만 저장하고 손상·외부 파일·미래 스키마·별칭 충돌은 보존한다. 북마크와 A/B는 성공적인 파일/붙여넣기/인코딩 재읽기에서 초기화되며 실패·취소에서는 유지한다. 키워드 강조 규칙은 현재 창에서 유지한다. 단축키 사용자 지정은 후속 범위다.

[추가 후보 전체 표](FEATURE-CANDIDATES.md)의 우선순위가 높음인 1~11번만 상세히 다룬다. 기능별 사용자 동작, 현재 코드와 연결할 지점, 경계 조건, 합성 데이터로 확인할 완료 기준을 정리한다. 타입 이름·파일 구성·기본값은 구현 제안이며 현재 존재하거나 확정된 API가 아니다.

목표는 원본을 유지하면서 문제 위치 탐색과 문맥 확인을 빠르게 만드는 것이다. 모든 기능을 한 번에 구현하기보다 공통 위치 매핑을 먼저 정리하고 작은 묶음으로 추가하는 편을 권한다. 실제 구현은 사용자가 지정한 범위와 순서에 따른다.

## 공통 기반과 기존 코드

현재 [LogModel.cs](../src/ThreadLogViewer.Core/LogModel.cs)는 원문을 공유하는 `LogLine`과 기록 범위인 `LogEntry`를 가진다. [LogProjection.cs](../src/ThreadLogViewer.Core/LogProjection.cs)는 표시 줄에서 원본 줄로 연결하는 `SourceIndexes`를 유지한다. 필터는 기록 전체를 남기며 원본 순서를 보존한다. 이 구조를 재사용한다.

[MainWindow.xaml.cs](../src/ThreadLogViewer.App/MainWindow.xaml.cs)의 `PublishView`에서 화면 문서를 교체한다. [LatestOperation.cs](../src/ThreadLogViewer.Core/LatestOperation.cs)는 최신 작업만 게시하게 하고, [LogRendering.cs](../src/ThreadLogViewer.App/LogRendering.cs)는 화면에 보이는 줄만 그린다. 새 기능도 이 흐름에 연결한다.

공통 구현 제안은 다음과 같다.

- **위치 기준:** 내부 원본 줄 인덱스는 0부터, 사용자에게 보이는 원본 줄 번호는 1부터 사용한다. 원본 줄·열·문서 식별자를 가진 작은 `SourcePosition` 또는 `ViewAnchor`를 공통으로 둔다.
- **문서 식별:** 새 파일, 붙여넣기, 인코딩 재읽기를 성공적으로 게시할 때 `SourceRevision`을 바꾼다. 같은 파일 경로라도 다시 읽은 데이터는 새 revision이다. 실패·취소는 기존 revision을 유지한다.
- **역방향 이동:** `SourceIndexes`는 원본 순서로 정렬되어 있으므로 원본 줄을 이진 탐색해 표시 줄로 바꾼다. 원본 줄마다 별도 딕셔너리를 만드는 방식은 피한다.
- **본문 소유 기록:** `LogLine.EntryIndex`로 기록을 찾고, `LogEntry.StartLineIndex`의 헤더를 사용한다. 본문에 별도 시간·소스 위치를 만들어 넣지 않는다.
- **화면 상태:** 기존 `LogProjection`을 참조하는 작은 `ViewState`에 필터 조건·문맥 모드·revision·표시 세대를 묶는다. 원문을 복제하지 않는다. 검색 결과와 강조는 생성 당시 표시 세대를 확인한 뒤 게시한다.
- **원본 오프셋:** 정규식·여러 줄 검색에 필요하면 각 줄의 원문 시작 오프셋을 한 번 계산해 공유한다. 원문과 줄 문자열을 결과마다 복사하지 않는다.
- **명시적 기록 투영:** 스레드뿐 아니라 선택된 기록 인덱스로 투영을 만들 수 있게 확장한다. `EntryCount`는 실제 남긴 기록 수로 계산한다. 현재처럼 선택 스레드에 속한 전체 기록 수만 계산하면 추가 키워드 조건으로 제외한 기록이 잘못 집계될 수 있다.
- **UI 분리:** 탐색·북마크, 검색, 필터, 설정, 시간 차이를 각각 작은 상태/로직 단위로 분리한다. `MainWindow`는 연결과 화면 게시를 맡는다. DB·웹 프레임워크·플러그인 계층은 만들지 않는다.

새 파일을 성공적으로 열면 문서별 북마크·검색 결과·시간 기준점·문맥 상태를 초기화한다. 필터 변경은 같은 원본 revision을 유지한다. 마지막 개행 뒤 편집기가 만드는 커서용 빈 행에는 원본 번호나 기준점을 부여하지 않는다.

## 1 원본 줄 번호로 이동

**사용 동작.** Ctrl+G 또는 이동 메뉴로 원본 줄 번호를 입력한다. 유효 범위는 원본 1~N줄이다. 이동은 현재 표시 줄이 아닌 원본 번호를 사용한다. 빈 파일에서는 이동을 비활성화한다.

**숨겨진 줄.** 현재 필터에 없는 줄이면 필터를 자동으로 해제하지 않는다. 해당 줄이 숨겨져 있음을 알리고, 8번 구현 후에는 해당 기록 문맥을 열어 이동하는 명시적 동작을 제공한다. 8번 전에는 안내와 기존 전체 선택으로 확인할 수 있게 한다.

**구현 제안.** Core의 작은 `LogNavigation`에 원본 줄 범위 검증과 원본 인덱스 → 표시 줄 이진 탐색을 둔다. UI는 반환된 표시 줄을 AvalonEdit 위치로 바꿔 caret 이동·스크롤한다. 원본 전체 재파싱이나 텍스트 검색은 필요 없다. 이동 입력 창과 단축키 처리는 App에 둔다.

**완료 기준.** 원본 100·105줄만 남은 화면에서 105 입력 시 표시 2번째 줄로 이동한다. 0·음수·N 초과·문자 입력을 거절한다. 줄바꿈된 화면의 여러 시각적 행을 원본 여러 줄로 세지 않는다. 숨긴 줄 안내, 빈 파일, 마지막 가상 빈 행을 확인한다.

## 2 현재 위치와 선택 정보

**사용 동작.** 상태줄에 현재 원본 줄과 열을 표시한다. 선택하면 실제 선택한 줄 수와 글자 수를 표시한다. 필터로 원본 100·105줄만 선택한 경우 선택 2줄이며 6줄로 표시하지 않는다. 원본 범위가 불연속이면 원본 100~105줄이라는 범위와 선택 2줄을 구분한다.

**계산 규칙.** 열은 편집기의 논리적 문서 열이며 1부터 표시한다. 탭과 자동 줄바꿈의 화면 폭을 열 수로 혼동하지 않는다. 선택은 시작 포함·끝 제외 범위로 처리한다. 끝이 다음 줄 첫 열이면 그 다음 줄 본문을 선택한 것으로 세지 않는다. 실제 빈 원본 줄을 선택한 경우에는 줄 수에 포함하고 가상 마지막 행은 제외한다.

글자 수의 첫 구현 제안은 선택한 Unicode 스칼라 값 수이며 개행도 선택된 텍스트에 포함한다. CRLF는 2개로 센다. 결합 문자·이모지 조합은 보이는 기호 하나와 수가 다를 수 있으므로 계산 기준을 도움말에 적는다. 편집기 열은 UTF-16 문서 위치 기준이므로 글자 수와 항상 같은 단위는 아니다.

**구현 제안.** caret·selection 변경을 작은 `SelectionSummary` 계산과 연결한다. 줄 수는 선택 세그먼트와 문서 줄 범위에서 구하고 원본 매핑을 적용한다. 글자 수를 세기 위해 대용량 `SelectedText`를 새 문자열로 만들지 않는다. 큰 선택은 짧게 지연한 백그라운드 계산으로 처리하고 revision·선택 세대를 확인해 최신 결과만 표시한다. 이벤트 구독은 문서/창 수명에 맞춰 해제한다.

**완료 기준.** 선택 없음, 한글·이모지·탭, 역방향 선택, CRLF/LF/CR, 실제 빈 줄, 다음 줄 첫 열에서 끝나는 선택을 검증한다. 사각형 등 여러 세그먼트 선택을 지원하는 경우 선택 세그먼트의 합집합으로 중복 줄을 제거한다. 큰 선택 중 UI 응답성과 결과 교체를 별도 GUI 확인한다.

## 3 북마크와 이름

**사용 동작.** Ctrl+F2로 현재 원본 줄의 북마크를 켜고 끈다. F2·Shift+F2로 다음·이전으로 이동한다. 여백 표시와 작은 목록을 제공하고 이름을 지정할 수 있게 한다. 예: 에러 시작, 재시도 시작, 복구 완료.

**첫 범위.** 북마크는 현재 실행 중인 문서에만 유지한다. 재실행 후 복원은 후보 26번이므로 이번 범위에서 제외한다. 같은 원본 줄의 북마크는 하나로 두고 이름을 갱신한다. 본문 줄에도 표시할 수 있다. 필터로 숨겨져도 북마크 자체는 유지한다.

**구현 제안.** 작은 `Bookmark`에 SourceRevision·원본 줄 인덱스·이름을 저장한다. 표시는 정렬된 원본 위치 목록으로 관리한다. 목록의 이전/다음 탐색은 원본 순서 기준으로 순환한다. 숨긴 위치는 즉시 필터를 바꾸지 않고 1번과 같은 안내/문맥 동작으로 연결한다. 여백에는 화면에 보이는 줄의 북마크만 그린다. 새 파일의 성공 게시 시 초기화한다.

**완료 기준.** 원본 105줄 북마크가 필터 전후 같은 줄을 가리킨다. 숨긴 북마크를 다시 표시하면 복원된다. 본문·빈 줄·마지막 줄에 표시할 수 있다. 파일 교체 성공 시 초기화하고 실패·취소 시 유지한다. 이름 변경은 원문·복사·내보내기에 섞이지 않는다.

## 4 검색 옵션 확장

**사용 동작.** 기존 검색창에 대소문자 구분, 단어 단위, 정규식, 범위를 추가한다. 범위는 현재 표시 기록을 기본으로 하고 전체 원본·현재 선택을 고를 수 있게 한다. 검색어와 옵션을 바꾸면 짧은 지연 후 다시 검색하고 기존 이전/다음 조작을 유지한다.

**검색 단위.** 기록 하나의 원문을 검색한다. 같은 기록 안의 헤더·본문·개행에 걸친 일치는 허용하지만 서로 다른 기록을 가로지르는 일치는 허용하지 않는다. 이 규칙은 기존 표시 문자열 전체 검색과 달라지는 의미를 명시한 제안이다. 떨어져 있던 원본 기록이 필터 결과에서 붙으면서 가짜 개행/정규식 일치가 생기는 문제를 막는다. 화면에 구분용 가짜 줄을 삽입하지 않는다.

**옵션 규칙.** 일반 문자열 검색에서 대소문자와 단어 경계를 적용한다. 단어 문자는 Unicode 문자·숫자·결합 문자·밑줄로 정의하고 테스트한다. 정규식과 단어 옵션을 동시에 쓸 때는 검색식 밖의 경계를 검사해 사용자가 입력한 정규식의 의미를 임의로 다시 쓰지 않는다. 정규식은 CultureInvariant를 기본으로 대소문자 옵션을 적용하고, Multiline/Singleline은 기본으로 켜지 않는다. 필요한 경우 식 안의 옵션을 사용하며 실제 CRLF/LF/CR은 정규화하지 않는다. 선택 범위는 실제 선택 구간만 검색하고 선택 끝 밖의 문자까지 일치하지 않게 한다.

정규식의 기본 `^/$`는 기록 검색 범위의 시작/끝 기준이며 `$`의 마지막 LF 앞 일치 등 .NET 엔진의 경계 규칙을 따른다. `.`은 기본으로 LF를 넘지 않고 CR은 별도 원문 문자로 취급한다. `(?m)`·`(?s)`를 사용하면 엔진의 해당 옵션 의미를 적용한다. CRLF/LF/CR 각각의 식 예와 테스트를 마련해 물리적 개행을 모두 같은 것으로 오해하지 않게 한다.

선택 범위 검색은 범위를 선택하는 시점의 원본 구간들을 고정한다. 결과 클릭·F3가 만든 선택은 검색 범위를 바꾸지 않는다. 새 선택을 범위로 쓰려면 선택 범위 다시 지정 동작을 실행한다. 여러 불연속 선택은 각 기록과 선택 세그먼트의 교집합별로 검색하며 조각을 이어붙이지 않는다. 필터/문서 교체로 선택 범위가 유효하지 않게 되면 자동으로 전체 검색으로 확대하지 않고 다시 지정하도록 안내한다.

**구현 제안.** `LogSearch`를 `SearchOptions`와 기록 범위를 받는 방식으로 확장한다. 결과의 위치는 원본 오프셋·길이·소유 기록으로 보존하고 이동 시 표시 위치로 변환한다. 일반 검색은 현재 취소 가능한 작은 구간 탐색을 유지한다. 정규식은 검색 시작 시 한 번 생성하고 유한한 match timeout을 지정한다. 예시 초기 timeout은 200ms이며 합성 측정 후 조정한다. 이는 성능 보장이나 작업 전체 제한 시간이 아니다. 기록/일치 사이에서 취소를 확인하며 timeout 내부 호출은 즉시 취소를 보장하지 않는다고 문서화한다.

잘못된 정규식과 timeout은 검색 실패로 안내하고 새 검색의 강조·결과 목록을 비운다. 이전 검색 결과를 새 검색어의 결과로 보이게 하지 않는다. 일부만 검색한 결과를 정상 완료처럼 게시하지 않는다. 0길이 정규식 일치는 엔진이 다음 위치로 진행하게 하고 결과 목록에는 허용하되 일반 사각형 강조는 그리지 않는다. 첫 100,000개 제한과 초과 표시를 유지하며 실제 추가 일치를 발견했을 때만 초과로 표시한다. 입력 변경·필터 변경·파일 변경마다 이전 검색을 취소하고 snapshot이 같은 결과만 게시한다.

**완료 기준.** case/CASE, 단어 부분 일치, 한글·밑줄 경계, 여러 줄 본문 일치, 숨긴 기록 포함 여부, 선택 끝 경계, 잘못된 식, timeout, 0길이 식, 첫 100,000개 초과, 오래된 결과 차단을 합성 데이터로 검증한다. 분리된 기록 사이의 가짜 일치가 없어야 한다.

## 5 검색 결과 목록

**사용 동작.** 하단의 접을 수 있는 검색 결과 패널에 원본 줄, 시간, 스레드, 일치 부분 주변 미리보기를 표시한다. 결과를 선택하면 실제 일치 위치로 이동한다. 본문에서 찾은 결과는 본문 원본 줄을 표시하고, 시간·소스 위치는 소유 헤더 기준임을 구분한다.

**결과 규칙.** 첫 구현은 일치 하나당 결과 하나로 두고 같은 줄의 여러 일치를 구분한다. 각 행에 검색어/옵션을 되풀이하지 않고 패널 상단에 검색 범위·조건·표시 결과 수를 둔다. 제한에 걸리면 전체 일치 수라고 주장하지 않고 첫 100,000개 표시라고 적는다. 전체 원본 검색의 숨긴 결과는 숨김 상태를 표시하고 1번/8번 탐색 정책을 사용한다.

**구현 제안.** Core에 원본 오프셋·길이·EntryIndex를 가진 `LocatedSearchHit`를 둔다. 원본 줄 시작 오프셋 인덱스로 해당 원본 줄·열을 찾는다. App은 결과 목록을 가상화하고 짧은 미리보기만 필요한 행에 만들어 원문 전체/기록 전체를 결과마다 복사하지 않는다. 오프셋만으로 현재 화면을 바로 움직이지 않고 결과 revision을 검사한다. 다중 행 결과는 시작 위치로 이동한 뒤 같은 기록의 일치 범위를 선택한다.

**완료 기준.** 본문 검색 결과가 올바른 원본 줄과 소유 헤더 정보를 가진다. 한 줄의 여러 일치·여러 줄 일치·숨긴 결과 이동·필터 변경 후 결과 갱신을 확인한다. 많은 결과에서 목록 스크롤 시 모든 행을 한 번에 생성하지 않는다.

## 6 여러 키워드 색상 강조

**사용 동작.** 키워드·색상·활성 상태를 갖는 규칙을 추가한다. 예: timeout은 주황, retry는 보라, command ID는 청록. 여러 규칙을 동시에 표시하며 개별 끄기·삭제를 지원한다. 첫 구현은 일반 문자열 규칙으로 시작한다.

**범위와 표시.** 강조는 현재 표시 기록에만 적용하고 필터 결과를 바꾸지 않는다. 빈 키워드는 거절한다. 규칙은 최대 8개, 강조 총량은 100,000개를 초기 상한으로 제안하고 부족 여부를 표시한다. 합성 성능 확인 후 상한을 조정할 수 있다. 초기에는 규칙을 세션에만 유지하며 저장은 후보 17번과 함께 검토한다.

**구현 제안.** `HighlightRule`과 별도 `LatestOperation`을 사용해 활성 검색과 규칙 강조의 취소 수명을 분리한다. 검색과 동일한 기록별 범위 탐색을 재사용한다. 스레드 배경 위에 키워드 강조, 그 위에 활성 검색 표시와 선택을 구별되게 그린다. 겹치는 규칙은 목록 순서를 우선순위로 삼는다.

현재 `SearchHighlightRenderer`는 고정 길이 일반 검색을 전제로 일치 끝 위치를 이진 탐색한다. 정규식/다중 키워드처럼 길이가 다르고 겹치는 구간에서는 끝 위치가 정렬되지 않을 수 있다. 시작 오프셋 정렬과 prefix maximum end를 사용하는 `HighlightIndex`, 또는 겹침을 해소한 비중첩 표시 구간으로 바꿔 가려진 긴 일치를 놓치지 않게 한다. 보이는 `VisualLines`에 해당하는 구간만 그리는 기존 원칙은 유지한다.

**완료 기준.** 세 키워드의 동시 표시, 길이가 다른 중첩 일치, 규칙 순서 변경, 개별 끄기, 필터 재적용, 테마 전환을 확인한다. 선택·검색·스레드 색을 구분할 수 있어야 한다. 상한 초과와 빠른 연속 변경에서 멈춤·오래된 강조 게시가 없어야 한다.

## 7 포함 및 제외 필터

**사용 동작.** 스레드 필터와 별도로 포함 키워드 목록과 제외 키워드 목록을 둔다. 포함 조건은 하나라도 포함(OR) 또는 모두 포함(AND)을 고른다. 제외 키워드 중 하나라도 맞으면 해당 기록을 제외한다. 예: 선택한 스레드 중 timeout 또는 retry가 있고 heartbeat가 없는 기록.

**정확한 결합.** `선택 스레드 AND 포함 조건 AND NOT 제외 조건`으로 평가한다. 포함 목록이 비면 포함 조건은 항상 참, 제외 목록이 비면 제외 조건은 항상 거짓이다. 조건 문자열을 임의로 공백으로 쪼개지 않고 줄/항목 단위로 입력해 띄어쓰기가 있는 문구도 검색한다. 빈 항목은 제거하고 완전히 같은 중복 조건은 정리한다. 첫 구현은 일반 문자열과 대소문자 옵션이며 정규식 필터는 후속 확장으로 둔다.

**기록 보존.** 헤더·본문 전체를 검사한다. 덤프 마지막 줄에 timeout이 있더라도 기록 전체를 남긴다. AND 키워드가 같은 기록의 서로 다른 본문 줄에 있어도 모두 포함으로 본다. 본문에 제외어가 있으면 해당 기록 전체를 제외한다. 서로 다른 기록 사이에서 조건이 이어지지 않는다.

**구현 제안.** Core의 작은 `EntryFilter` 또는 `FilterOptions`에 스레드·포함·제외·결합 모드를 둔다. 일치 기록 인덱스를 먼저 계산한 뒤 공통 기록 투영을 만든다. `LogProjection.EntryCount`와 `SelectedThreads`의 의미를 분리한다. 스레드 목록 건수는 전체 원본 건수를 유지하고 상태줄에 필터 결과 건수를 표시해 조건 변경으로 목록 건수가 흔들리지 않게 한다.

필터 입력은 짧게 지연해 기존 `LatestOperation` 흐름으로 실행한다. 성공 시에만 조건과 투영을 함께 확정하며 취소·실패 시 마지막 성공 조건과 화면을 유지한다. 검색·강조를 새 표시 snapshot에서 다시 수행한다. 내보내기는 확정된 투영의 원본 기록만 기존 `LogExporter`로 저장한다.

**완료 기준.** AND/OR·빈 목록·중복·띄어쓰기 문구·포함과 제외 동시 일치·본문 일치를 검증한다. 남긴 기록의 원본 줄·개행·순서가 정확해야 한다. 결과 0건, 취소 시 조건 복원, 원본 경로/기존 파일 내보내기 차단도 회귀 확인한다.

## 8 전체 스레드 문맥 보기

**사용 동작.** 현재 기록이나 검색 결과에서 전후 문맥 보기를 실행한다. 기본은 앞 20건·뒤 20건과 중심 1건이며 건수를 조절한다. 현재 스레드/키워드 필터를 잠시 우회해 원본 순서의 모든 스레드를 보여 준다. 중심 기록을 표시하고 기존 필터로 돌아가기를 제공한다.

**경계 정책.** 단위는 줄이나 초가 아닌 기록 건수다. 중심이 여러 줄 덤프 본문이면 소유 기록을 중심으로 삼는다. 파일 시작/끝에서는 실제 존재하는 기록만 표시한다. 같은 시각·잘못된 시각·미분류 기록도 원본 순서대로 포함한다. 시간 정렬로 다시 배열하지 않는다.

**구현 제안.** Core의 `LogContext`가 중심 EntryIndex와 앞뒤 건수로 기록 인덱스 구간을 만든다. 공통 명시적 기록 투영으로 원문·줄 매핑을 유지한다. App의 작은 문맥 상태에 이전 필터와 위치 앵커를 보관한다. 단일 화면에서 모드를 전환하며 새 창/두 번째 전체 문서를 만들지 않는다. 복귀 시 이전 조건으로 다시 투영해 큰 표시 문자열을 중복 보관하는 기간을 줄인다.

문맥 모드에서는 현재 표시 범위의 검색·키워드 강조·표시 건수가 문맥을 기준으로 동작한다. 전체 원본 검색은 계속 전체 원본을 대상으로 하며 선택 범위 검색은 4번의 고정 범위 규칙을 따른다. 검색 패널에 적용 범위를 명시해 문맥에 없는 결과의 의미를 구분한다. 내보내기는 표시한 문맥 전체이며 대화상자와 기본 파일명에 문맥 내보내기임을 명시한다. 스레드/키워드 조건을 바꾸려면 기존 필터로 복귀한 뒤 적용하게 해 숨은 이중 필터 상태를 만들지 않는다.

**완료 기준.** 본문 선택, 시작/끝 경계, 같은 시각의 다른 스레드, 미분류, 잘못된 헤더를 확인한다. 20+1+20건은 최대 41건이며 여러 줄 기록 때문에 줄 수는 더 많을 수 있다. 복귀 시 원래 필터·위치가 복원된다. 문맥 내보내기도 원본 줄·개행을 보존하고 기존 파일을 덮어쓰지 않는다.

## 9 필터 변경 후 위치 유지

**사용 동작.** 필터를 바꿔도 같은 원본 줄과 가능한 열을 유지한다. 화면 상단의 원본 위치도 가능한 범위에서 유지해 읽던 문맥을 잃지 않게 한다. 현재 줄이 숨겨지면 가까운 표시 기록으로 이동하고 현재 위치가 숨겨졌다는 상태를 짧게 표시한다.

**복원 규칙.** 원본 위치를 이진 탐색한다. 정확한 줄이 없으면 원본 줄 거리상 가까운 표시 줄을 택하고 같은 거리면 뒤쪽 줄을 택한다. 모든 기록을 숨겼으면 위치는 대기 앵커로 보존한다. 다시 표시하면 사용자 이동이 없었던 경우에만 복원한다. 새 파일의 성공 게시에서는 이전 파일 앵커를 재사용하지 않는다.

**구현 제안.** `ViewAnchor`에 revision·caret 원본 줄/열·상단 원본 줄과 상대 화면 위치·가로 스크롤을 저장한다. 최신 필터 결과가 성공한 것을 확인한 뒤 `PublishView`에서 기존 문서를 교체하기 직전에 현재 화면의 앵커를 캡처한다. 작업 중 사용자가 이동한 최신 위치도 이때 반영한다. 이미 0줄 화면이라 캡처할 위치가 없으면 마지막 유효 앵커를 사용한다. 새 문서를 성공적으로 게시한 후에만 복원한다. 새 줄이 짧으면 열을 해당 줄 길이에 맞춰 제한한다. 자동 줄바꿈·글꼴 변경 시에는 원본 위치를 우선하며 픽셀 위치의 완전 동일 복원을 약속하지 않는다.

사용자가 명시적으로 이동하면 그 위치를 새 유효 앵커로 삼고 프로그램의 복원 이벤트와 구분한다. 필터 취소/실패 시 기존 화면과 위치를 유지한다. 연속 필터 작업은 마지막 성공 snapshot만 복원한다. 여러 줄 선택 자체의 복원은 불연속 범위 정책이 필요하므로 첫 구현은 caret와 화면 위치에 한정한다.

**완료 기준.** 유지되는 줄, 사라지는 줄, 앞뒤 동률, 마지막 줄, 결과 0줄 후 복원, 열 제한을 확인한다. 연속 필터·취소·실패·작업 중 사용자 이동·새 파일 교체를 따로 검증한다. 1·3·5·8·11번 이동 기능은 같은 매핑을 사용한다.

## 10 설정 저장

**사용 동작.** 다음 실행에서도 테마·글자 크기·행 간격·자동 줄바꿈·스레드 패널 폭을 복원한다. 기본값으로 되돌리기 동작을 둔다. 첫 범위에는 파일 경로·로그 본문·검색어·필터·북마크·A/B 기준점을 저장하지 않는다. 최근 파일/분석 상태는 후보 26번이다.

**저장 위치 제안.** 포터블 배포 폴더의 앱 전용 `user-data/ui-settings.json`을 사용한다. 개발에서도 프로젝트 안의 같은 전용 폴더를 사용하고 `.gitignore`에 넣는다. 이 경로는 구현 제안이며 이번 문서 작업에서는 폴더나 설정 파일을 만들지 않는다. `%AppData%`·레지스트리·원본 로그 폴더에 자동 쓰기하지 않는다. 배포 폴더가 쓰기 불가하면 현재 세션 설정으로 계속 동작한다.

**구현 제안.** App의 `UiSettings`는 단순 값과 스키마 버전을 가진다. `SettingsStore`는 작은 JSON 읽기·검증·저장을 맡는다. 앱 소유 표식과 지원 스키마를 확인한 파일만 갱신한다. 글자 크기는 지원 목록, 테마/간격은 허용값, 폭은 창의 유효 범위로 검증한다. 로딩 중 UI 이벤트로 설정을 다시 저장하지 않게 억제하고 변경 저장은 짧게 모아서 실행한다.

앱이 소유한 파일의 갱신은 같은 폴더의 임시 파일에 쓴 뒤 원자 교체한다. 모르는 기존 파일, 손상된 JSON, 지원하지 않는 미래 버전은 보존하고 기본값을 사용한다. 앱 소유 표식만으로 임의 사용자 파일을 덮어쓰지 않도록 경로를 앱 전용 위치에 고정한다. 현재 열린 원본이 설정 파일과 같은 경로/별칭이면 쓰기를 차단하고, 설정 경로의 reparse point·링크 별칭을 통한 다른 위치 쓰기도 차단하는 보수적 정책을 적용한다. 원본 보호를 우회하는 설정 저장 기능이 되어서는 안 된다.

첫 범위에서는 여러 창의 설정 변경 병합을 하지 않고 마지막 정상 저장값을 사용한다. 잠김·권한·디스크 실패 시 현재 창의 설정은 유지하며 저장 실패를 안내한다. 구현 시 설정 경로가 프로젝트 밖으로 바뀌는 작업은 기존 프로젝트 승인 규칙을 따른다.

**완료 기준.** 정상 왕복, 값 범위 오류, 손상·미래 스키마·모르는 기존 파일 보존, 임시 파일 쓰기 실패, 쓰기 불가, 동시 창, 원본/설정 경로 충돌을 프로젝트 내부 임시 디렉터리로 테스트한다. 재실행 복원은 별도 GUI 확인한다. 설정 저장 전후 원본 바이트는 같아야 한다.

## 11 두 지점 시간 차이

**사용 동작.** 현재 줄 우클릭 또는 작은 시간 차이 패널에서 A/B 기준점을 지정한다. 원본 줄·소유 헤더 줄·스레드·원래 시각을 보여 주고 `B − A`를 계산한다. A/B 교환, 각 위치 이동, 초기화, 결과 복사를 제공한다. 예: `.113`에서 `.125`까지는 `+00:00:00.012 · 12 ms`.

**본문 처리.** 덤프 본문은 자체 시간이 없으므로 EntryIndex의 헤더 시간을 사용한다. 예: 원본 421줄을 지정하면 헤더 418줄의 시간을 사용한다고 표시한다. 첫 시간 헤더 전 줄이나 잘못된 헤더는 이전 유효 시간을 대신 가져오지 않는다. 유효 시간 없는 기준점은 계산 불가로 표시한다.

**시간 의미.** 결과 이름은 기록 시간 차이다. 실제 처리 시간이라고 단정하지 않는다. 24시간 초과 누적 시각은 그대로 사용하고 날짜를 만들어 넣지 않는다. `23:59:59 → 00:00:00`은 `−23:59:59`이며 자동으로 하루를 더하지 않는다. 음수는 기준점 순서·자정 통과·시계 역행 가능성을 안내하되 원인을 단정하지 않는다. 서로 다른 스레드도 비교할 수 있다.

**구현 제안.** Core의 작은 `LogTimeDifference`에 원본 줄 기준점 해석과 계산을 둔다. 현재 `TimeOfDay`는 이름과 달리 누적 시간을 허용한 TimeSpan이고 파서는 소수초 1~7자리를 정수 ticks로 해석한다. 기준점에는 선택한 원본 줄과 실제 헤더 위치, revision을 저장한다. 계산은 `checked(b.Ticks - a.Ticks)`로 하며 예상 밖 범위 오류는 결과 상태로 돌려준다. 현재 유효 입력은 0~TimeSpan.MaxValue이므로 두 값의 차이는 signed TimeSpan 범위 안이다.

시간 표시는 ticks의 정수 나눗셈으로 누적 시간을 만들고, 24시간마다 접히는 Hours 성분만 사용하지 않는다. ms 보조 값은 decimal 계산으로 작은 차이를 보존한다. 원래 시간 문자열과 소수 자릿수도 보여 주며 100ns 표현 단위가 장비의 실제 측정 정확도라는 뜻은 아니다. 기준점 해석과 계산은 O(1)이므로 전체 검색·재파싱·새 장기 작업을 만들지 않는다.

필터 변경은 기준점을 유지하고 숨긴 기준점 상태를 표시한다. 새 파일·붙여넣기·인코딩 재읽기를 성공 게시했을 때만 기준점을 초기화한다. 실패·취소는 유지한다. 같은 기록의 헤더와 본문을 A/B로 지정하면 차이는 0이다.

**완료 기준.** 12ms·1 tick 차이, 초/분/시간 경계, 24시간·100시간 초과, 같은 기록 본문, 유효하지 않은 시간, 자정 전후 음수, A/B 교환을 검증한다. `00:00:00`과 `256204778:48:05.4775807`의 최대 범위 차이도 확인한다. 필터 매핑·가상 마지막 행·파일 성공/실패 교체 시 수명 규칙을 확인한다.

## 이번 상세 범위에서 제외한 기능

다중 탭·파일 비교·실시간 추적·타임라인·세션 복원·북마크 영구 저장·필터 프리셋·편집 메모·정규식 필터·정규식 강조 규칙은 이번 11개 첫 구현 범위에 포함하지 않는다. 기존 후보 번호는 전체 표에 유지한다. 로그 원본 편집·자동 덮어쓰기·온라인 분석·로그인·텔레메트리·DB·플러그인 구조도 추가하지 않는다.
