# 구현 범위와 후속 계획

## v0.8.0 검토 후 수정

- 비동기 F5와 프리셋 준비가 최신 입력을 보존하도록 재확인하며 탭별 탐색 진행 상태를 분리한다.
- 설정 저장 실패를 다시 시도하고 여러 파일 열기·검색 취소·닫은 탭 보관 정리 결과를 유지한다.
- 작업 영역/DPI 창 크기, 펼친 필터·북마크 스크롤, 본문·스레드 공간, 검색 오류 폭과 편집 메뉴 대상을 보강한다.
- 긴 줄 구간 표시/전체 표시 선택을 저장하며 원문·줄·검색·복사·내보내기 매핑을 유지한다. 줄별 중복 참조와 임시 할당을 줄이고 디코딩·문서 생성의 취소를 보강한다.
- 명시적 분석 상태와 필터·강조 프리셋을 로컬 새 JSON 파일로 저장한다. 원문 지문·원본 종류/경로·범위·8 MiB 한도·취소·기존 파일 보호를 확인한다. 자동 시작 복원과 DB는 추가하지 않는다.
- 빌드·회귀·합성 화면·실제 GUI·측정 성능·수명 검사·배포 결과는 [v0.8.0 검증 기록](VALIDATION-v0.8.0.md)을 따른다. 이전 후보와 검증 기록은 아래에 보존한다.

## v0.1 기반 기능

1. Windows x64, C# / .NET 10 / WPF / AvalonEdit. UI 앱, Core, Tests의 3개 프로젝트.
2. 파일 전체를 한 번 디코딩하고 원본 문자열에 대한 행/필드 슬라이스와 스레드 요약을 생성.
3. 표시 인덱스와 원본 줄 번호를 분리. 필터는 파싱 결과만 사용하며 원본 순서를 보존.
4. 읽기 전용 AvalonEdit, 다중 행 선택·복사, 줄바꿈, 글자 크기, 고정폭 글꼴.
5. 고정 스레드 색상, 체크박스 필터, 최초/마지막으로 관측한 유효 시각. 날짜·생성 시점·실행 기간은 추론하지 않음.
6. 현재 표시된 문자열의 검색·강조·순환 이동. 원본과 다른 새 파일로 UTF-8 내보내기.
7. 읽기·파싱·필터 문서 생성·검색·내보내기는 백그라운드에서 실행. 취소 토큰과 세대 번호로 최신 결과만 게시.
8. 합성 테스트, 빌드·GUI 검증 구분, 10/100 MiB 성능 측정, self-contained 폴더 ZIP.
9. 파일 드래그 앤 드롭 및 파일/로그 텍스트 붙여넣기. 텍스트 입력은 실제 원본 경로가 없는 읽기 전용 문서로 처리하고 기존 로딩·취소·최신 결과 게시 흐름을 공유.

## v0.2 워크벤치 UI

- WPF 컨트롤 스타일을 통일하고 다크/라이트 테마, 얇은 툴바, 통합 상태줄을 적용.
- 스레드 색상은 같은 ID에 같은 팔레트 위치를 사용하며 테마에 맞춰 명도를 조절.
- WPF 복합 글꼴의 줄 간격으로 기본/좁은 간격을 제공. 원본 텍스트·복사·줄 번호는 변경하지 않음.
- 추가 UI 패키지나 웹 런타임 없이 기존 WPF/AvalonEdit를 유지.

## v0.3 여러 줄 기록

- 시간 값을 24시간 시계로 제한하지 않고 두 자리 이상의 시간과 원래 소수초 정밀도로 해석.
- 시간 헤더부터 다음 시간 헤더 전까지의 물리적 줄을 명시적인 기록 범위로 유지. 필터·색상·내보내기에 같은 범위를 사용.
- 시간 헤더 없는 본문을 별도 스레드로 재파싱하지 않음. 시간 헤더 없는 접두부만 기존의 독립 행 처리 유지.
- 기록 건수와 원본 줄 수를 구분하고, 연속 본문 줄을 파싱 실패로 집계하지 않음.
- 중단된 GUI 검증 재개, 여러 줄 기록 회귀 테스트 및 10/100 MiB 합성 성능 재측정.

## v0.4 분석과 화면 흐름

- 원본 줄 이동·선택 정보·이름 있는 북마크·고급 검색·결과 목록·문구 강조·내용 필터·주변 보기·위치 유지·표시 설정 저장·시간 차이 구현.
- v0.4.1에서 주변 로그 / 두 기록 시간 차이 / 문구 강조를 구분하고 현재 기준·필터 적용 상태·내보내기 범위를 안내.
- 빌드·자동 WPF 테스트와 실제 GUI 확인은 [v0.4.1 검증 기록](VALIDATION-v0.4.1.md)에 구분해 보존.

## v0.5 메뉴와 여러 로그 탭

- 파일 / 편집 / 보기 / 분석 / 도움말 메뉴와 단축키 힌트. 자주 사용하지 않는 수동 인코딩은 파일 메뉴 내부에 배치.
- 파일 다중 선택·다중 파일 드롭·클립보드 로그를 각각 탭으로 열고 Ctrl+Tab / Ctrl+Shift+Tab / Ctrl+W 제공. 같은 파일은 기존 탭으로 이동.
- 탭마다 원본·표시 문서·스레드/내용 필터·검색 조건·북마크·문구 강조·A/B 기준·주변 보기·위치를 현재 실행 중에 보존. 본문은 읽기 전용이며 파일을 덮어쓰지 않음.
- BOM 없는 입력은 엄격한 UTF-8에 실패할 때만 엄격한 CP949로 대체하고 추정임을 표시. 잘못된 BOM 입력·UTF-32·둘 다 실패하는 입력은 거절.
- v0.4.0 붙여넣기 종료 이벤트의 처리되지 않은 InvalidDataException을 확인해 예외 처리 보완. 지원하지 않는 입력·빈 입력·OLE 제공자 예외·긴 로그 다음 짧은 로그를 합성 자료로 회귀 확인.
- 검증 범위와 10 MiB 디코딩 단계만의 실측은 [v0.5.0 검증 기록](VALIDATION-v0.5.0.md)에 별도 기록. 실제 GUI·탭 전환 성능은 미측정.

## v0.6 줄 우클릭과 범위 탭

- 고정 분석 패널을 폐지하고 실제 클릭한 원본 물리적 줄을 우클릭 작업의 대상으로 고정. 필터·탭이 바뀐 뒤 남은 오래된 대상은 거절.
- 세션 분리 시작과 끝을 포함하는 원본 줄 범위를 새 읽기 전용 탭으로 제공. 필터가 숨긴 중간 줄을 포함하며 원본 개행·줄 번호와 소유 헤더 정보를 보존.
- 분리 탭의 필터·전체 원본 검색·고정 선택 검색·주변 보기·원본 이동·내보내기 모두 해당 범위 안으로 제한. 중첩 분리는 현재 범위 내부만 허용.
- 시간 기준 줄 지정 후 비교 줄에서 시간 차이를 실행. 유효한 시각만 갱신하고 간단한 원본 위치·부호 있는 결과를 표시. 별도 A/B 분석 패널 없이 사용.
- Shift+F8 문구 강조 관리 창: 선택 문구 미리 채우기·최대 8개·적용/취소·탭별 독립 규칙.
- 분리 시작·시간 결과를 간단한 표시줄로 안내하고 시간 기준/비교는 원본 줄 여백에 A/B 표식. 우클릭 하위 메뉴에 시간 결과·이동/북마크·텍스트 동작과 주변 범위 5/20/100 또는 직접 지정 0~10,000 제공.
- F3 다음 / F4 이전 검색, Shift+F3 이전 별칭 유지. 원본·탭별 시간·강조·분리 시작 위치의 수명을 분리.
- 구현·빌드·회귀·배포·GUI·성능은 [v0.6.0 검증 기록](VALIDATION-v0.6.0.md)에 구분. 기존 v0.5.0 배포·검증 기록 보존.

## 다음 개선 후보 — 2026-10-05 보관

사용자 요청으로 현재 로그 뷰어의 완성도 개선 후보를 보관한다. 제안한 구현 우선순위이며 아직 완료한 기능이나 확정 일정은 아니다. 구체적인 소스 근거와 검증 공백은 [v0.6.3 UX 검토](UX-REVIEW-v0.6.3.md)를 따른다.

1. 즉시: 진행률과 마지막 결과 안내를 분리해 완료·취소·거절·실패를 항상 표시한다. 늦은 결과가 다른 탭에 게시되지 않도록 기존 보호를 유지한다.
2. 즉시: 강조 관리의 새 문구 추가와 기존 변경 적용을 분리한다. 기존 문구·색을 직접 편집하고, 끄기·삭제한 문구가 입력칸 때문에 재추가되지 않게 한다.
3. 즉시: 필터 결과 0건의 원인을 구분하고 내용 필터 해제·전체 필터 해제를 제공한다. 필터가 접혀 있어도 적용 여부를 표시한다.
4. 다음: 같은 실행 중 닫은 탭을 원문·범위·분석 상태와 함께 복원한다. 보관 개수와 메모리를 제한한다.
5. 다음: 상태를 유지하는 별도 파일 새로 고침을 제공한다. 인코딩·필터·강조를 유지하고 변경된 원본의 북마크·시간·위치를 재검증한다. 실패·취소는 기존 상태를 보존한다.
6. 다음: 탐색 뒤로·앞으로와 스레드 ID 찾기로 반복 탐색을 줄인다.
7. 병행 검증: 합성 큰 파일·다중 탭·긴 한 줄·많은 검색 결과의 실제 입력 반응, 취소 지연과 메모리를 측정하고 작은 화면·125/150/200% DPI를 확인한다. 측정에 따라 최적화 범위를 정한다.

추가 후보는 붙여넣은 전체 원문을 현재 표시 결과와 구분해 새 파일로 내보내기, 사용자가 명시적으로 저장하는 분석 작업 재개다. 원본 읽기 전용·기존 파일 비덮어쓰기·원본 줄/개행 보존·로컬 오프라인 실행과 기존 화면 설정 저장 형식을 유지한다.

데스크톱 GUI 비교를 위해 사용자 연결 후 Figma에 편집 가능한 1360×860 시안 3개를 작성했다. [A 차분한 다크](https://www.figma.com/design/eg60MTlax3Ft4yv4UviNpQ?node-id=5-51)를 기본 추천으로 두고, [B 고밀도 분석](https://www.figma.com/design/eg60MTlax3Ft4yv4UviNpQ?node-id=6-192)과 [C 밝은 집중](https://www.figma.com/design/eg60MTlax3Ft4yv4UviNpQ?node-id=6-561)을 비교한다. 합성 로그만 사용했으며 실제 앱 UI·패키지·런타임은 변경하지 않았다.

시안에는 스레드 ID 검색·상시 결과 안내·시간 결과 직접 액션 등 후속 UX 제안이 포함된다. 현재 구현 완료 기능을 뜻하지 않는다. Figma 폰트는 사용 가능한 Noto Sans KR와 Roboto Mono로 대체했으며, 실제 WPF 구현의 Windows 폰트와 스레드 고유 색·관측 시각·원문/공백 보존은 유지 대상으로 둔다.

세 시안의 편집 가능한 레이어, 폰트, 1360×860 영역 경계와 컨테이너 내부 배치를 구조 검사했다. A는 최종 스크린샷을 확인했다. B·C는 Figma Starter 연동 호출 한도로 스크린샷 확인을 완료하지 못했다. 이번 작업은 디자인·문서 작업이며 빌드·자동 테스트·실제 앱 GUI·성능 측정은 새로 실행하지 않았다. 포커스·비활성 상태·긴 파일명/ID·DPI와 실제 창 크기 변화는 UI 구현 단계의 검증 항목이다.

## 후속 기능 (미구현 버튼을 만들지 않음)

보관한 개선 후보 1~6과 스레드 배경색 강화·토글을 v0.7.0에 구현한다. 7번은 새 합성 앱 성능 harness로 큰 파일·다중 탭·긴 줄·많은 검색 결과·취소·dispatcher 지연과 작은 화면/DPI 렌더를 측정한다. 비표시 WPF·bitmap DPI 측정을 실제 사용자 입력이나 실제 모니터 DPI 검증으로 보고하지 않는다. 최종 결과와 남은 확인 범위는 [v0.7.0 검증 기록](VALIDATION-v0.7.0.md)을 따른다.

검색 결과 영역의 드래그 높이 조절·목록 접기/펼치기·선호 높이 및 접힘 저장은 v0.6.4 작업에 반영한다. 세부 검증과 미확인 범위는 [v0.6.4 검증 기록](VALIDATION-v0.6.4.md)을 따른다. 위 Figma 전체 시안의 구현 완료를 뜻하지 않는다.

- 별도 메모장 편집 기능은 후보이며 이번 여러 파일 보기 요청에 포함하지 않음. 구현한다면 원본 뷰어와 별도 문서/저장 수명주기부터 설계.
- 타임라인: 날짜 누락과 자정 통과·시계 역행 구분 정책부터 설계.
- 북마크·분석 상태의 명시적 저장/불러오기는 v0.8.0에 구현. 전체 작업 공간의 자동 시작 복원은 후속 범위.
- 기본 기능 안정화 후 단축키 사용자 지정.
- 실시간 따라가기: 파일 교체, 부분 행, 회전 처리.
- 대용량 최적화: 메모리 매핑/구간 로딩/표시 투영 증분 처리. 백그라운드 문서 생성도 작은 청크로 취소 가능하도록 개선.

1~11번은 v0.4에 구현했다. 원본 이동·선택 정보·세션 북마크·고급 검색·결과 목록·다중 강조·포함/제외·전체 문맥·위치 유지·표시 설정 저장·A/B 시간 차이를 제공한다. v0.5에 28번 다중 파일 탭을 구현하고 22번 인코딩 선택의 자동/CP949 메뉴 범위를 반영했다. UTF-8/UTF-16 수동 선택을 포함한 나머지 후보는 확정 일정이 아니다. 단축키는 [기본 단축키 표](SHORTCUTS.md)를 따르며 수동 테스트의 기대 결과와 실제 검증 결과는 구분한다.

자동 테스트, 실제 GUI 조작, 콘솔 벤치마크를 각각 기록한다. 예상 시간이나 예상 메모리는 측정값으로 보고하지 않는다.
