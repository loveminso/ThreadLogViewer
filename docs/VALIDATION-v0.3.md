# v0.3.0 검증 기록 — 2026-09-16

## 변경

- `[014:15:50.113] [T 1124525]` 및 24시간을 넘는 시간 값 지원. 원래 문자열과 소수초 정밀도 보존.
- 줄 처음의 시간 헤더부터 다음 시간 헤더 직전까지 하나의 기록. 빈 줄·덤프·본문의 다른 스레드 표식도 같은 기록에 포함.
- 물리적 원본 줄과 기록 범위를 별도로 보존. 필터는 메모리의 기록 범위만 사용하며 파일을 다시 읽거나 파싱하지 않음.
- 헤더 없는 첫 부분은 기존 독립 행 처리 유지. 스레드 없는 새 헤더는 미분류 기록. 잘못된 시간 모양의 헤더도 이전 기록을 끝냄.
- 스레드 목록은 기록 건수, 상태줄은 기록 건수와 원본 줄 수를 구분. 연속 본문은 파싱 실패로 집계하지 않음.
- 신규 런타임 의존성 없음. 실행 중 네트워크 기능 추가 없음.

- Windows x64, .NET SDK 10.0.401 / 런타임 10.0.12.
- `build.cmd`: Release 성공, 경고 0 / 오류 0.

- 기존 행 단위 덤프 테스트를 명시된 새 기록 규칙으로 갱신. 세 자리 시간 필드 추출, 반복 필터 전환과 원본 번호, 스레드 없는 기록, 잘못된 헤더의 경계, 24시간 초과/정밀도/범위 초과 시간, 여러 줄 기록의 UTF-8 내보내기와 원본 바이트 보존 추가 검증.
- 기존 인코딩, 취소, 오래된 작업 결과 차단, 검색 범위, 파일/텍스트 입력, 테마 대비 및 AvalonEdit 실제 행 높이 회귀 테스트 통과.

## 실제 GUI 검증

사용자가 이전 Esc 중단 후 재개를 요청하여 실제 Release WPF 앱을 직접 조작했다. 아래는 자동 테스트와 별개로 확인한 항목이다.

- `multiline-elapsed.log` 8건/17줄, T 1124525의 정확한 첫/마지막 시간과 한글 표시.
- T 1124525 ‘단독’: 2건/6줄, 원본 번호 **3, 4, 5, 6, 9, 10**. 빈 줄과 `[T7]`로 시작하는 본문도 같은 배경색과 묶음으로 표시.
- T 1124525 체크 해제: 0줄. 다시 선택: 2건/6줄 복원.
- 기본 → 좁은 간격 → 기본 간격. 실제 행 높이 변화와 번호 보존.
- 다크 → 라이트 → 다크. 본문·여백·툴바·검색/선택 영역의 색상 변경 확인.
- Ctrl+F로 현재 표시 중인 로그에서 `1124525` 검색: 3개. F3의 1/3, Shift+F3의 3/3 순환 이동과 두 테마의 강조·선택 가독성 확인. Esc로 검색 닫기.
- Ctrl+A로 여러 줄 선택, 일반 문자 키로 원문 수정 불가 확인. Ctrl+C 후 Ctrl+V로 새 읽기 전용 로그 열기. 붙여넣은 2건/6줄의 본문이 복사한 본문과 같고 여백 번호가 섞이지 않음. 줄 번호 1부터 재시작, 원본 인코딩 알 수 없음, CP949 재읽기 비활성화 확인.
- GUI ‘필터 결과 내보내기’ 대화상자에서 `local-data/gui-v0.3-filtered.log` 생성. 파일 바이트 검사로 선택된 원본 6줄·개행과 정확히 일치, UTF-8 BOM 없음 확인.
- 파일 열기 대화상자로 10 MiB 합성 로그 열기: 120,271건 / 121,881줄. 진행 상태와 취소 버튼 표시 확인.
- 글자 크기 14 → 20, 가로 스크롤 막대 이동, 자동 줄바꿈, 줄바꿈 중 세로 스크롤 확인. 접힌 화면 줄에 원본 번호를 중복 표시하지 않음.
- 10 MiB 로그에서 ‘전체 해제’ 0줄, ‘전체 선택’ 121,881줄 복원 확인.

이전 v0.2에서 Esc로 중단됐던 **라이트 테마, 좁은 간격, 검색·필터·복사·내보내기 GUI 확인을 완료**했다.

## 합성 성능 실측

`benchmark.cmd 10`, `benchmark.cmd 100`을 각각 별도 콘솔 프로세스로 한 번 실행. 세 자리 누적 시간, 16개 스레드, 한글, 덤프, 빈 줄을 생성한다. 필터는 T 3, T 7, 미분류 선택. WPF 배치/렌더링 시간은 제외하며 전체/필터 AvalonEdit 문서를 모두 유지한 프로세스의 메모리다.

## 확인하지 못한 항목 / 한계

- 실제 탐색기 창에서 앱 창까지의 파일 드래그 제스처는 도구의 창 간 드래그 제한으로 미확인. 실제 WPF FileDrop 데이터의 파일 판별·입력 회귀 테스트는 통과. 기존 파일 붙여넣기 GUI 이력은 v0.1 기록 참고.
- 다른 Windows PC, 다른 DPI, 시스템 고대비, 장시간 사용은 미확인. 테마·간격 설정은 재실행 후 저장되지 않음.
- 100 MiB는 콘솔 벤치마크를 실행했으며 이번 실제 GUI 대용량 검증은 10 MiB까지. 대용량 GUI에서 취소 버튼의 클릭 타이밍 및 빠른 연속 열기는 이번 수동 시나리오에 포함하지 않음. 취소 토큰과 최신 결과 차단은 자동 테스트로 검증.
- 100 MiB에서 최대 작업 집합 약 1,023 MiB. 전체 메모리 로딩 구조이므로 큰 파일에서는 충분한 RAM이 필요함.
- 시간 헤더가 본문 줄 처음에 그대로 등장하면 새 기록으로 인식. 날짜·자정 통과의 실제 경과 시간·스레드 생성 시각은 추론하지 않음.
