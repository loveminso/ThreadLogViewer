# ThreadLog Viewer v0.6.3 기능·UX 점검

점검일: 2026-10-04 · 대상: 현재 프로젝트 소스 v0.6.3

## 판단 요약

로그 입력, 원본 보존, 필터·검색, 선택·복사, 분석, 탭 관리와 화면 설정의 주요 기능은 구현되어 있다. 기존 자동 테스트 222개는 이번 실행에서 모두 통과했다. 다만 자동 테스트 통과가 모든 사용자 흐름의 편리함을 보장하지는 않는다.

먼저 고칠 부분은 **보이지 않는 작업 피드백**, **강조 관리의 의도와 다른 자동 추가**, **0건 결과에서 원인과 맞지 않는 복구 안내**다. 그다음에는 파일 새로 고침과 닫은 탭 복구로 반복 분석의 재작업을 줄이는 것이 좋다. 기능 수를 늘리기보다 기존 작업이 끝났는지, 어떤 조건이 적용됐는지, 잘못한 작업을 어떻게 되돌리는지 명확하게 만드는 순서를 권한다.

이번 작업은 점검과 개선안 정리다. 프로그램 소스, 기술 스택, 저장 형식과 사용자 파일은 수정하지 않았다.

## 점검 범위와 증거의 한계

- 앱·핵심 로직·관련 테스트·기능 안내 문서를 읽고, 화면 흐름과 핵심 흐름을 병렬 조사한 뒤 독립 검토로 지적 사항을 교차 확인했다.
- 현재 세션의 일반 조사 에이전트를 사용했다. `.codex` 사용자 정의 역할의 로딩·호출 검증을 수행한 것은 아니다.
- 기존 로컬 SDK와 패키지 캐시로 Release 빌드 및 전체 자동 테스트를 실행했다. 새 도구를 설치하지 않았다.
- 이번 테스트 실행이 생성한 합성 WPF 화면 PNG를 직접 읽었다. 비표시 `RenderTargetBitmap` 렌더링이며 실제 창의 마우스·키보드 조작과 다르다.
- 실제 GUI 조작 도구가 현재 세션에 없어 파일 대화상자, 실제 클립보드, 모달 강조 관리창, 실제 DPI·다중 모니터 흐름은 수동 재현하지 않았다.
- 모든 기능군의 구현과 관련 자동 검증을 확인했다. 모든 조합·입력 장치·사용 환경에서 정상이라고 판정한 것은 아니다.
- 테스트와 성능 측정에는 합성 데이터만 사용했다. 실제 로그와 기존 사용자 설정을 열거나 변경하지 않았다.

## 우선 개선할 구체적 문제

### 1. 작업 결과와 일부 실패 이유가 상시 보이지 않음 — 최우선

**현재 동작:** `OperationStatus`가 작업 중에만 보이는 `WorkPanel` 안에 있다. 완료 시 `FinishWork`가 패널을 숨긴다. 붙여넣기 실패, 빠른 강조 거절, 설정 저장 실패는 메시지 문자열만 바꾸므로 기본 화면에서 반응이 없는 것처럼 보인다. 성공·취소 메시지도 완료 직후 숨는다. 건수 표시 툴팁에 마지막 메시지가 연결되어 있지만, 사용자가 그 위치에 마우스를 올려야 확인할 수 있다.

**불편한 작업:** 빈 클립보드 붙여넣기, 9번째 강조 문구 추가, 불연속 선택 강조 시 실패 이유를 찾기 어렵다. 내보내기 후 저장 성공 여부와 경로도 바로 확인하기 어렵다. 강조 계산 제한·메모리 오류는 숨긴 `KeywordStatus`에만 기록되는 별도 문제가 있다.

**개선:** 진행률·취소 버튼과 마지막 결과 메시지를 분리한다. 성공·취소·오류를 보이는 상태 영역에 남기고 강조 제한·오류도 그 영역으로 전달한다. 내보내기 성공에는 저장 경로를 확인할 수 있는 동작을 제공한다.

**완료 조건:** 위 거절·실패와 정상 완료·취소를 합성 데이터로 발생시켰을 때 사용자가 마우스를 올리지 않아도 결과와 다음 행동을 읽을 수 있어야 한다. 문자열 검사뿐 아니라 실제 노출 여부도 검증한다.

근거: `MainWindow.xaml:125,131,135`, `MainWindow.xaml.cs:125,129,186,304`, `MainWindow.Clipboard.cs:16`, `MainWindow.Settings.cs:39,65`, `MainWindow.QuickHighlight.cs:25,50`, `MainWindow.Analysis.cs:110,136,140`. 파일 열기·내보내기 등의 `ShowError` 경로는 실제 창에서 MessageBox를 띄우므로 모든 오류가 숨겨진다는 뜻은 아니다.

### 2. 강조 관리의 “적용”이 기존 규칙 변경과 문구 추가를 섞음 — 최우선

**현재 동작:** 선택 문구를 새 입력칸에 미리 채운다. ‘적용’을 누르면 입력칸에 남은 문구를 새 활성 규칙으로 추가한다. 기존 `timeout` 위에서 관리창을 열어 해당 규칙을 끄거나 삭제해도 같은 입력이 남아 있으면 새 `timeout` 규칙이 추가되어 의도가 상쇄된다. 8개 규칙에서는 단순 켜기·끄기 적용도 입력칸을 비워야 진행할 수 있다.

**개선:** ‘추가’와 ‘기존 변경 적용’을 분리하고, 중복 문구는 기존 규칙 편집으로 연결한다. 등록된 행에서 문구·색을 직접 수정할 수 있게 한다. 현재는 색 변경에 삭제→재입력→색 선택→추가→적용이 필요하며, 기존 색 변경이 가능하다는 안내와 실제 UI가 다르다.

**완료 조건:** 기존 문구 끄기·삭제 후 적용 시 재추가되지 않아야 한다. 8개를 유지한 채 색·활성 상태만 바꿀 수 있어야 한다. 취소는 이전 규칙을 그대로 유지해야 한다. 실제 모달 관리창의 입력·추가·적용 흐름을 검증해야 한다.

근거: `HighlightPrompt.cs:44,59,74,89,91,105`, `MainWindow.LineActions.cs:255`, `docs/FEATURE-TEST-GUIDE.md:154`. 기존 `LineActionsTests.cs:86`은 대화상자 결과 주입을 검사하며 이 모달 조작 흐름을 검사하지 않는다. 위 판단은 독립 소스 검토로 확인했으며 실제 모달 GUI 재현은 미실행이다.

### 3. 내용 필터로 0건일 때 복구 안내가 맞지 않음 — 우선

**현재 동작:** 0건 화면은 스레드 전체 선택 또는 체크박스를 안내한다. 그러나 일치하지 않는 내용 필터가 원인이면 스레드를 전체 선택해도 여전히 0건이다.

**개선:** 스레드 조건과 내용 조건을 구분해 원인을 안내하고, 빈 결과 화면에 ‘내용 필터 해제’와 ‘모든 필터 해제’를 제공한다. 입력 전 빈 탭, 원본 빈 파일과 필터로 0건인 상태를 계속 구분한다.

**완료 조건:** 포함·제외 조건 때문에 0건인 화면에서 안내된 동작으로 결과를 복원할 수 있어야 한다. 복구는 원본이나 다른 탭의 조건을 변경하지 않아야 한다.

근거: `MainWindow.xaml.cs:223,225`, `MainWindow.Navigation.cs:154,162`의 내용 조건 해제와 적용 조건·초안 구분.

## 낮은 우선순위 및 추가 GUI 확인이 필요한 항목

- **검색 결과 영역:** 결과가 있으면 자동으로 펼쳐지고 창 높이에 따라 70~135px로 조절된다. 사용자 직접 크기 조절·결과만 접기는 없다. 검색창을 유지한 채 결과 목록만 접는 동작과 세로 크기 조절을 검토한다. 숨긴 원본의 검색 결과로 이동하면 주변 보기로 전환되고 스레드·내용 필터가 잠기므로 이 관계도 더 명확하게 안내한다. 기존 주변 보기 안내·필터 복귀 버튼은 유지한다. `MainWindow.Search.cs:101,135`, `MainWindow.AnalysisUi.cs:47`, `MainWindow.Settings.cs:46`, `MainWindow.xaml:228,408`.
- **작은 화면·DPI:** 기본 1360×860, 최소 1040×600이며 왼쪽 패널은 최소 275px다. 현재 합성 렌더와 최소 창 자동 테스트는 통과하지만 실제 125/150/200% DPI와 작은 작업 영역은 미확인이다. 작업 영역에 맞는 초기 창 크기와 왼쪽 패널 접기를 검토한다. `MainWindow.xaml:1,140`, `WindowFeatureTests.cs:153`.
- **비슷한 탭 제목:** 같은 파일명·분리 탭을 많이 열면 전체 경로 툴팁을 반복 확인해야 한다. 이름 충돌 시 부모 폴더 보충과 분리 탭 이름 변경을 검토한다. `MainWindow.Sessions.cs:30,135,223`.
- **첫 입력의 발견성:** 빈 탭은 +/Ctrl+N, Ctrl+O/Ctrl+V를 이미 안내한다. 안내 영역에 직접 ‘파일 열기’, ‘로그 붙여넣기’ 버튼을 추가하면 단축키를 모르는 사용자의 첫 작업을 줄일 수 있다. 현재 입력 기능이 없다는 뜻은 아니다.

## 권장 구현 순서와 유지할 동작

1. 보이는 결과·실패 안내, 강조 관리의 자동 추가 분리, 0건 원인별 복구 안내를 수정한다.
2. 파일 새로 고침과 같은 실행 중 닫은 탭 복원을 추가해 분석 상태의 재작업을 줄인다.
3. 시간 결과·선택 구간 분리·내보내기 이름 충돌 등 반복 작업의 단계를 줄인다.
4. 많은 스레드·작은 화면·큰 파일 사용성은 실제 GUI 측정을 통해 우선순위를 조정한다.

원본 읽기 전용, 기존 파일 비덮어쓰기, 실제 줄·개행·원본 순서 보존, 로컬·오프라인 실행, 탭별 상태 독립은 유지한다. 이미 구현된 우클릭 대상 표시·선택 보존, 빠른 강조, 단축키 접근, 탭 스크롤, 주변 보기 복귀를 누락 기능으로 취급하지 않는다. 이 문서는 개선안을 제시하며 해당 기능을 구현했다고 보고하지 않는다.
