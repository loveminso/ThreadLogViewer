# v0.1 검증 기록 — 2026-09-15

## 환경 및 도구

- Windows x64 10.0.26200.0, 논리 프로세서 12개, Git 2.51.0.windows.1.
- 빈 폴더이며 상위 저장소가 없어 독립 로컬 Git 저장소 초기화. 원격·업로드·push 없음.
- 초기 환경은 SDK 없이 .NET 6 런타임만 있었음. 사용자 승인 후 공식 SDK ZIP을 SHA512 검증하고 `.tools/dotnet/`에 **.NET SDK 10.0.401** 설치.
- 사용 런타임은 .NET / Windows Desktop **10.0.12**. 시스템 PATH와 기존 .NET은 변경하지 않음.
- SDK·NuGet 다운로드는 개발 단계에서 사용. 앱 코드에 네트워크·로그인·서버·텔레메트리 기능 없음.

## 실제 GUI 확인

Computer Use로 실제 Windows 앱 창을 관찰·조작함.

- self-contained Release EXE 실행, 파일 선택 창에서 합성 UTF-8 17줄 열기. 한글·빈 줄·미분류·원본 번호·배경색·통계·UTF-8 ‘추정’ 표시 확인.
- T 3 단독 5줄: 원본 번호 **1, 3, 9, 11, 15**. 전체 선택으로 복구. 최초/마지막 기록은 자정 통과를 포함한 파일 순서 그대로 표시.
- Ctrl+F로 필터 안의 `testcase` 4개 검색. 노란 강조·짙은 파란 선택, F3 및 Shift+F3 순환 이동.
- Ctrl+A 다중 행 선택, Ctrl+C 및 검색 입력란 붙여넣기. 선택 텍스트에 여백 번호 없음.
- 선택한 로그에 `READ_ONLY_CHECK` 입력을 시도해도 문서 내용 불변.
- 긴 16번 행 자동 줄바꿈과 글자 크기 14→24 변경. 줄바꿈된 시각 행에 원본 번호를 반복하지 않음.
- GUI 내보내기로 `local-data/gui-filtered.log` 생성 후 별도 읽기 검증: **5줄, UTF-8 BOM 없음, 원문 순서, 여백 번호 없음**.
- Debug GUI에서 10/100 MiB 파일 열기와 T 3 단독 필터 확인.

### 파일 끌어오기 및 붙여넣기 추가 검증

- 변경 후 Release WPF 창에서 17줄 합성 로그를 Ctrl+A/C로 복사한 뒤 Ctrl+V로 열기 확인. 한글·빈 줄·미분류·색상 유지, 제목은 ‘붙여넣은 로그’, 줄 번호는 붙여넣은 텍스트 기준으로 안내함.
- 붙여넣은 로그의 상태줄은 ‘클립보드 Unicode · 원본 인코딩 알 수 없음’, CP949 다시 읽기는 비활성화됨.
- 검색창에서 Ctrl+V는 검색어만 입력하고 현재 17줄 로그를 대체하지 않음.
- 실제 탐색기에서 `samples/line-mapping.log`를 Ctrl+C로 복사한 뒤 앱에서 Ctrl+Shift+V: 파일 경로·110줄·스레드 통계·UTF-8 추정 표시 확인. CP949 다시 읽기가 다시 활성화됨.
- 파일 끌어놓기의 데이터 판독·거부는 자동 테스트로 확인. 실제 탐색기→앱 창 사이 마우스 드래그는 Computer Use 도구가 다른 창으로 향하는 드래그를 허용하지 않아 **GUI 검증 미완료**. 구현 완료와 실제 마우스 검증을 구분함.
- 아래 성능 측정은 입력 기능 추가 전의 실제 결과이며, 이번 변경 후 재측정하지 않음.

## Release 성능 측정

각각 별도 프로세스에서 `benchmark.cmd 10`, `benchmark.cmd 100`을 **한 번씩 실제 실행**. 생성 직후 읽어 OS 파일 캐시가 영향을 줄 수 있으며 디스크 콜드 캐시 측정이 아님. 다른 사용자 앱은 실행 중이었음.
T 3·T 7·미분류를 선택했고 전체·필터 문서를 모두 메모리에 유지함.

| 항목 | 10 MiB | 100 MiB |
| --- | ---: | ---: |
| 실제 바이트 | 10,485,785 | 104,857,641 |
| 전체 줄 | 123,296 | 1,232,948 |
| 필터 결과 줄 | 16,839 | 168,377 |
| 읽기 + 디코딩 + 파싱 | 264.33 ms | 1,637.04 ms |
| 전체 투영 + AvalonEdit 문서 생성 | 202.43 ms | 854.52 ms |

| 프로세스 최대 작업 집합 | 152.46 MiB | 959.51 MiB |

**WPF 배치·렌더링은 콘솔 수치에서 제외됨.** 메모리는 콘솔 프로세스의 최대 작업 집합이며 GUI 자체의 최대 메모리가 아님.
원본 JSON: [10 MiB](measurements/benchmark-10MiB.json), [100 MiB](measurements/benchmark-100MiB.json).
공개용 기록에는 합성 파일 경로를 프로젝트 상대 경로로 표시함. 측정값은 변경하지 않음.

## 미확인 및 한계

- 실제 회사 PC·회사 보안 정책·다른 Windows 버전·다른 DPI/글꼴은 미확인. 실제 회사 로그·사내 코드 사용 없음.
- 인터넷을 물리적으로 차단한 별도 PC에서는 미시험. self-contained 배포이며 실행 시 네트워크를 요구하는 앱 코드 없음.
- 저메모리·디스크 부족·권한 실패·링크 경쟁·극단적인 긴 한 줄·수 GB 파일·수천 스레드 장시간 스트레스는 미실행.
- 취소와 최신 결과 게시 보호는 자동 테스트했고, GUI의 모든 연속 열기·필터·취소 타이밍 조합을 전수 시험하지 않음.
- 검색 강조/이동은 첫 100,000개까지. 전체 파일을 메모리에 유지해 100 MiB에서도 메모리 사용량이 큼.
- 코드 서명, 편집 탭, 타임라인, 시간 차이, 북마크, 실시간 따라가기는 후속 범위.
