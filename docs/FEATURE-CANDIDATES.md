# ThreadLog Viewer 기능 추가 후보

작성일: 2026-10-03 · 최초 기준: v0.3.0 · 갱신: v0.5.0

로그에서 문제 위치를 찾고, 다른 스레드의 문맥을 확인하고, 중요한 지점을 표시하고, 필요한 결과를 추출하는 작업을 개선하기 위한 37개 후보와 최초 우선순위를 보관한다. **높음인 1~11번은 v0.4.0에, 28번 다중 파일 탭은 v0.5.0에 사용자 지시에 따라 구현했다.** 22번은 자동 UTF-8/CP949 읽기와 메뉴의 수동 CP949 선택을 반영했으며 수동 UTF-8/UTF-16 선택은 후속이다. 나머지는 후보이며 확정 일정이 아니다. 실제 사용법과 확인 결과는 [테스트 방법](FEATURE-TEST-GUIDE.md), [v0.5 검증 기록](VALIDATION-v0.5.0.md)에 있다.

우선순위가 **높음인 1~11번**의 동작과 구현 제안은 [높은 우선순위 기능 상세 설계](HIGH-PRIORITY-FEATURES.md)에 정리했다. 개발 부담은 현재 구조를 기준으로 한 상대적 판단이며, 개발 기간이나 실측 성능을 뜻하지 않는다. 이후 수정할 때 기존 번호를 유지하면 번호로 기능을 다시 지정하기 쉽다.

## 우선 적용 제안

첫 묶음은 원본 줄 이동과 위치 유지, 현재 위치 표시, 세션 내 북마크, 설정 저장이다. 다음 묶음은 검색 옵션과 결과 목록, 포함·제외 필터, 여러 강조색이다. 그다음 전체 스레드 문맥 보기와 시간 차이를 추가한다. 기능별 상세 순서와 의존성은 상세 설계 문서에서 확인한다.

이 순서는 개발 제안이다. 사용자가 지정한 기능과 순서가 우선하며, 문서를 저장한 것만으로 앱 기능을 변경하거나 개발을 시작하지 않는다.

## 설계 기준

- 원본 로그와 기존 사용자 파일을 보호한다. 보기와 분석은 읽기 전용이며 내보내기는 새 파일만 생성한다.
- 필터·북마크·검색 결과·시간 기준점은 원본 위치에 연결한다. 화면 줄 번호는 필터에 따라 달라진다.
- 여러 줄 기록의 헤더와 본문을 함께 취급한다. 본문에서 일치한 필터도 기록 전체를 남긴다.
- 원본 순서를 유지한다. 날짜 없는 자정 통과나 시계 역행을 임의로 보정하지 않는다.
- 현재 WPF/AvalonEdit와 작은 Core 로직을 유지한다. DB·웹 프레임워크·플러그인·온라인 서비스는 추가하지 않는다.
- 설정은 앱의 전용 위치에 저장한다. 로그가 있는 폴더를 설정 저장 위치로 사용하지 않는다.

현재 구조와 후속 계획은 [기존 계획](PLAN.md), 사용자 기능은 [README](../README.md), 기존 실측은 [v0.3 검증 기록](VALIDATION-v0.3.md)을 참고한다. 100 MiB 합성 로그의 약 1,023 MiB 최대 작업 집합은 기존 콘솔 단회 측정이며 GUI 렌더링은 제외했다. 이번 문서 작성에서 성능을 다시 측정하지 않았다.
