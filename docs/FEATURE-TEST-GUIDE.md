# ThreadLog Viewer 기능 테스트 방법

작성일: 2026-10-03 · 기준 버전: v0.6.3

높음 후보 11개가 구현되었다. 아래 절차는 사용자가 직접 실행해 확인할 수 있는 방법과 기대 결과다. [기본 단축키 표](SHORTCUTS.md)와 함께 사용한다. 사용자 지정 단축키는 후속 범위다.

이번 새 빈 탭의 빌드·자동 테스트·GUI 여부는 [v0.6.3 검증 기록](VALIDATION-v0.6.3.md), 자동 검증 명령은 [TESTING](TESTING.md)에 기록한다. 이전 여러 줄 선택·즉시 강조는 [v0.6.2](VALIDATION-v0.6.2.md), 줄 선택은 [v0.6.1](VALIDATION-v0.6.1.md), 줄 우클릭·범위 탭·강조 창은 [v0.6.0](VALIDATION-v0.6.0.md), 메뉴·탭은 [v0.5.0](VALIDATION-v0.5.0.md), 분석 화면은 [v0.4.1](VALIDATION-v0.4.1.md), 합성 성능은 [v0.4](VALIDATION-v0.4.md)에 보존한다. 자동 WPF 테스트와 합성 콘텐츠 렌더링은 실제 사용자 화면 확인과 구분한다.

## 테스트 준비

실제 회사 로그 대신 프로젝트의 합성 샘플만 사용한다. 회사 로그를 테스트 기록이나 공개 문서에 복사하지 않는다.

| 자료 | 용도 |
|---|---|
| [100줄 예시](../samples/demo-100-lines.log) | 화면·검색·색상·일반 필터 확인 |
| [새 기능용 9줄 예시](../samples/analysis-features.log) | 검색 옵션·포함/제외·12ms 시간 차이 확인 |
| [원본 줄 매핑](../samples/line-mapping.log) | T 3 선택 시 원본 100·105줄만 남는지 확인 |
| [여러 줄 누적 시간](../samples/multiline-elapsed.log) | 덤프·빈 줄·소유 헤더·미분류·잘못된 시간 확인 |
| [인코딩 샘플 설명](../samples/README.md) | UTF-8/UTF-16/CP949 확인 |
| [빈 파일](../samples/empty.log) | 0줄 상태와 기능 비활성화 확인 |

개발 소스의 빌드와 자동 테스트는 프로젝트 폴더 PowerShell에서 실행한다. 필요한 SDK/패키지가 없는 경우 새 도구를 자동 설치하지 않고 기존 개발도구 승인 규칙을 따른다.

```powershell
.\build.cmd
.\test.cmd
```

테스트 결과 파일은 프로젝트의 TestResults 폴더에 생성된다. 두 명령의 결과는 실제 화면 확인과 별도로 기록한다. 설치된 도구/캐시만 사용한 오프라인 검증 명령과 결과는 검증 기록을 따른다.

현재 소스로 화면을 실행할 때는 다음 명령을 사용한다.

```powershell
.\run.cmd
```

이번 배포 실행 파일은 `artifacts/ThreadLogViewer-v0.6.3-win-x64/ThreadLogViewer.exe`다. 기존 배포 폴더들은 보존한다. 새 경로의 EXE를 실행하고 제목에 v0.6.3이 표시되는지 확인한다. 배포 생성 여부는 검증 기록을 따른다. 아래는 사용자가 직접 확인할 절차이며 이번 작업에서 앱을 자동 실행하거나 제어하지 않았다.

## + / Ctrl+N 새 빈 탭 확인

새 빈 탭은 로그 입력을 기다리는 읽기 전용 자리다. 텍스트를 편집하거나 원본 파일을 저장하는 문서가 아니며, 입력 전에는 Ctrl+V / Ctrl+O를 안내한다.

| 순서 | 조작 | 기대 결과 |
|---:|---|---|
| 1 | 파일을 열기 전 탭줄 오른쪽 + 확인 후 클릭. 파일 → 새 탭, Ctrl+N도 사용 | +가 처음부터 보이며 `새 탭 1`, `새 탭 2`, `새 탭 3` 생성. 서로 독립적인 빈 탭이며 단축키는 메뉴에 Ctrl+N으로 표시 |
| 2 | 빈 탭에서 본문 입력·찾기·분석·내보내기 상태 확인 | 본문 읽기 전용. 로그 입력 전 찾기·줄 이동·분석·내보내기 메뉴는 비활성화. Ctrl+V / Ctrl+O 안내와 0줄 표시 |
| 3 | 빈 탭을 선택한 뒤 합성 로그 텍스트 복사 → Ctrl+V | 현재 빈 자리 하나를 로그 탭으로 바꿈. 탭 개수 유지, 줄 번호 1부터. 다른 탭 보존. 같은 로그 탭에 다시 붙여넣으면 별도 새 로그 탭 |
| 4 | +로 빈 탭 생성 후 Ctrl+O에서 서로 다른 합성 파일 2개 선택 | 첫 성공한 파일이 빈 자리를 채우고 다음 파일은 별도 탭. 원본 내용·경로·개행 유지 |
| 5 | 빈 탭에서 이미 열어 둔 같은 파일을 다시 열기 | 기존 파일 탭으로 이동. 중복 파일 탭을 만들지 않고 사용하지 않은 빈 탭도 남음 |
| 6 | 빈 탭에서 지원하지 않는 클립보드 내용 붙여넣기 또는 열기 실패 상황 비교 | 실패 안내 후 같은 빈 탭과 개수 유지. 이후 유효한 로그로 채울 수 있음. 제공자 예외·첫 실패 후 성공 파일은 합성 자동 회귀로 검사 |
| 7 | 빈 탭에서 samples/empty.log 열기 | 파일 경로가 있는 일반 빈 파일 탭으로 바뀌고 ‘빈 파일’ 안내. 입력을 기다리는 새 빈 탭과 구별 |
| 8 | 로그 탭에 스레드 필터·떨어진 행 선택·검색·강조·북마크·시간 기준 설정 후 + 생성. 다시 이전 로그 탭으로 이동 | 새 빈 탭에는 이전 분석 상태가 섞이지 않음. 돌아간 로그 탭의 필터·선택·검색·강조·북마크·시간 위치 복원 |
| 9 | 빈 탭을 닫고 다시 생성. 이어 모든 탭을 닫은 뒤 + 확인 | 이름 번호를 재사용하지 않음. 마지막 탭을 닫아도 +가 남아 새 빈 탭 생성 가능 |
| 10 | 여러 빈 탭을 만든 뒤 창 폭을 줄이고 탭줄 스크롤. 검색 입력창에 포커스를 두고 Ctrl+N | +는 탭줄 오른쪽 고정 위치에 남고 탭과 겹치지 않음. Ctrl+N은 입력창 포커스와 관계없이 새 빈 탭 생성 |
| 11 | 큰 합성 파일 읽기 중 +로 새 빈 탭 생성 | 이전 읽기를 취소하고 새 탭 유지. 늦은 읽기 결과와 일괄 열기 무효화는 지연 합성 회귀로 검사 |

탭은 현재 실행 중에만 유지한다. 파일을 열거나 붙여넣어도 원본·기존 파일을 수정하지 않는다. 위 절차는 사용자가 직접 확인할 기대 결과이며 실제 GUI 통과 기록이 아니다.

## 메뉴와 여러 로그 탭 확인

상단에는 파일 / 편집 / 보기 / 분석 / 도움말 메뉴가 있다. 메뉴 항목 오른쪽의 단축키를 익히면서 사용할 수 있다. 탭은 현재 실행 중에만 보관하며 본문을 편집하거나 원본 파일을 저장하지 않는다.

| 순서 | 조작 | 기대 결과 |
|---:|---|---|
| 1 | 파일 메뉴를 펼치고 새 탭, 파일 열기, 클립보드 로그 열기, 인코딩 메뉴 확인 | Ctrl+N / Ctrl+O / Ctrl+Shift+V 등 단축키 힌트 표시. CP949 버튼은 로그 제목 옆에 없고 파일 → 인코딩으로 다시 읽기 안에 있음 |
| 2 | Ctrl+O에서 demo-100-lines.log와 analysis-features.log를 함께 선택 | 파일별 탭 2개. 현재 로그의 건수·스레드·원본 줄 번호와 파일명이 일치함 |
| 3 | 첫 탭에서 한 스레드를 단독 선택하고 내용 필터·검색어·북마크 이름·강조·시간 기준점을 설정. 둘째 탭에서 다른 조건 설정 | 각 탭에 독립적인 조건과 원본을 사용함. 다른 파일의 북마크·검색 조건·강조·시간 위치가 섞이지 않음 |
| 4 | 탭 클릭, Ctrl+Tab, Ctrl+Shift+Tab으로 여러 번 왕복 | 해당 탭의 스레드·내용 조건, 검색 조건, 북마크, 강조, A/B, 현재 위치·선택·스크롤을 복원함. 화면 설정인 테마·글자 크기는 앱 전체에 적용됨 |
| 5 | 첫 탭을 주변 보기로 만든 뒤 둘째 탭으로 이동했다가 복귀 | 첫 탭의 주변 기준·범위·앞뒤 건수·필터 잠금 상태를 유지함. 기존 필터로 돌아가기를 누르면 첫 탭의 이전 필터·위치로 복귀 |
| 6 | 이미 열려 있는 파일을 Ctrl+O로 다시 열기 | 중복 탭을 늘리지 않고 기존 파일 탭으로 이동함 |
| 7 | Ctrl+W 또는 탭의 ×로 한 탭 닫기. 마지막 탭도 닫기 | 다른 탭의 조건은 유지함. 마지막 탭을 닫으면 빈 로그 안내와 파일 없는 상태로 돌아가며 +는 계속 보임. 닫은 탭은 다시 열어야 함 |
| 8 | 로그가 있는 탭에서 합성 텍스트를 복사해 Ctrl+V, 이어서 더 짧은 합성 텍스트를 복사해 Ctrl+Shift+V | 매번 새 탭을 만들고 기존 탭 유지. 새 빈 탭이 활성화된 경우에는 그 자리를 채움. 줄 번호는 각 붙여넣은 텍스트의 1부터 시작. 짧은 텍스트로 바뀌어도 종료하지 않음 |
| 9 | 탐색기에서 합성 .log/.txt 파일 여러 개를 복사해 Ctrl+V 또는 여러 파일을 창에 끌어 놓기 | 파일별 탭으로 열림. 같은 파일은 기존 탭으로 이동. 파일 원본을 이동·삭제·수정하지 않음 |
| 10 | 검색창에 Ctrl+V, 같은 포커스에서 Ctrl+Shift+V 비교 | Ctrl+V는 검색어에 붙여넣음. Ctrl+Shift+V는 클립보드 로그를 열며 활성 빈 탭이 있으면 채움 |
| 11 | 로그를 연 상태에서 이미지 등 지원하지 않는 클립보드 내용을 붙여넣기 | 실패 안내를 상태줄에 표시하고 기존 로그·탭을 유지함. 실제 클립보드 잠금·OLE 지연 자료 예외는 합성 자동 테스트로 별도 확인 |
| 12 | mixed-cp949.log를 보통 파일 열기로 열기 | 한글이 표시되며 하단에 CP949로 해석, UTF-8 실패 후 대체, 추정이라고 안내함. 수동 버튼을 먼저 누를 필요 없음 |
| 13 | 파일 → 인코딩으로 다시 읽기 → 자동 판별 / 한국어 (CP949) 선택 | 현재 파일 탭을 다시 읽고 중복 탭을 만들지 않음. 수동 다시 읽기는 파일을 새로 해석하므로 해당 탭의 분석 조건을 초기화함. 붙여넣은 텍스트 탭에서는 재읽기 비활성화 |
| 14 | 보기 메뉴에서 테마·행 간격·글자 크기·자동 줄바꿈 변경. Ctrl++ / Ctrl+- / Ctrl+0 사용 | 본문·번호·선택·메뉴가 해당 테마로 바뀜. 체크 표시와 실제 설정이 일치함. Ctrl+0은 글자 크기 14. 원문과 원본 번호 유지 |
| 15 | 합성 로그 원본 또는 이미 있는 파일 경로로 내보내기 시도 | 거절 안내. 원본과 기존 파일 모두 덮어쓰지 않음. 새 경로로 내보내면 현재 탭의 표시 범위만 UTF-8로 저장 |

원본 변경 확인에는 합성 샘플의 작업 전후 SHA-256을 비교한다. 여러 탭의 메모리는 탭 수와 파일 크기에 따라 증가한다. 프로그램 종료 후 탭·검색·북마크를 복원하는 기능은 이번 버전에 없다. 위 기대 결과는 실제 GUI 통과 기록으로 간주하지 않는다.

## 줄 번호 드래그·Ctrl 선택·복사 확인

줄 번호 영역에서 **왼쪽 버튼을 누른 채 드래그**해 연속한 표시 줄을 선택하고 **Ctrl+줄 번호 또는 Ctrl+본문 클릭**으로 떨어진 줄을 추가·해제한다. 복사는 선택한 표시 줄만 원본 순서로 모으고 개행을 추가·정규화하지 않는다.

| 순서 | 조작 | 기대 결과 |
|---:|---|---|
| 1 | analysis-features.log의 줄 번호에서 2줄부터 6줄까지 왼쪽 드래그, 이어서 6줄부터 2줄로 역방향 드래그 | 양 끝을 포함한 원본 2~6줄 선택. 역방향도 같은 줄 집합. 원문 변경 없음 |
| 2 | 6줄 선택 후 Ctrl+2줄 번호 클릭 → Ctrl+C | 클릭 순서와 무관하게 원본 2줄 다음 6줄을 복사. 사이의 3~5줄과 여백 번호는 없음 |
| 3 | 같은 상태에서 Ctrl+본문 6줄 클릭 | 6줄만 선택 해제. 2줄은 유지. 다시 누르면 6줄 추가 |
| 4 | CRLF/LF/CR 혼합 합성 로그에서 떨어진 줄과 개행 없는 마지막 줄 선택 후 복사 | 각 선택 줄의 실제 개행 유지. 마지막 줄에 개행을 만들지 않음. 일반 텍스트 붙여넣기 대상에서 내용 비교 |
| 5 | line-mapping.log에서 T 3만 표시한 뒤 원본 100~105줄의 여백을 드래그해 복사 | 현재 표시한 원본 100·105줄만 복사. 필터로 숨긴 101~104줄은 없음 |
| 6 | 긴 원본 한 줄을 자동 줄바꿈하고 여백의 아래쪽에서 드래그 시작. 드래그를 충분히 움직인 후 화면 위/아래 가장자리에서 유지 | 감긴 한 줄을 같은 물리적 줄로 취급. 다음 물리적 줄까지 움직이면 해당 줄도 선택. 가장자리에서는 원본 물리적 줄 단위로 자동 스크롤하며 문서 끝에서 멈춤. 단순 클릭만으로 선택 범위가 늘지 않음 |
| 7 | 한 탭에서 2·6줄, 다른 탭에서 다른 줄을 선택한 뒤 왕복 | 각 탭의 선택 행과 원본 번호를 복원. 복사도 현재 탭의 선택만 사용 |
| 8 | 행 선택 후 본문에서 `timeout`만 일반 드래그 선택하고 Ctrl+C | 일반 문구만 복사. 이전 불연속 행을 함께 복사하지 않음 |
| 9 | 불연속 행 선택 후 검색창의 선택 범위 지정을 사용해 숨긴 중간 줄의 문구 검색 | 선택한 행 안에서만 검색. 불연속 간격을 연결해 숨긴 줄까지 검색하지 않음. 선택 정보의 줄 수·문자 수도 선택 집합 기준 |
| 10 | 분리 탭에서 여러 표시 줄 선택·Ctrl+C, 가상 마지막 행·아래 빈 공간에 시도 | 범위 내부 표시 행만 복사. 원본 번호 없는 공간은 행 선택 대상으로 받지 않음 |
| 11 | 여러 줄을 선택한 상태에서 필터 변경 | 새 표시 투영을 게시하면 이전 행 선택과 진행 중인 드래그를 해제. 이전 보기의 숨긴 행을 잘못 복사하지 않음 |

## 줄 번호 클릭·우클릭 대상 표시 확인

줄 번호 클릭은 **원본 물리적 한 줄 전체 선택**, 우클릭 색은 **현재 메뉴의 작업 대상 표시**다. 두 표시는 서로 독립적이다. 실제 파일 대신 합성 샘플을 사용하며 개행은 실제 존재하는 부분만 선택한다.

| 순서 | 조작 | 기대 결과 |
|---:|---|---|
| 1 | analysis-features.log에서 원본 2줄의 줄 번호 클릭 | 본문 2줄 전체와 실제 개행 선택. 여백 번호는 텍스트에 포함하지 않음. 커서는 2줄 시작에 유지 |
| 2 | 그 상태에서 Ctrl+F2, Shift+F8 사용 | 북마크는 다음 줄 대신 2줄에 지정. 한 문구로 선택된 해당 줄을 즉시 강조·해제. 원문 변경 없음 |
| 3 | line-mapping.log에서 T 3 단독 보기 후 원본 105줄 번호 클릭 | 화면의 두 번째 표시 줄인 원본 105줄만 선택. 숨긴 원본 101~104줄이나 앞의 100줄을 섞지 않음 |
| 4 | 긴 합성 한 줄을 자동 줄바꿈한 뒤 그 줄의 아래쪽 여백 클릭 | 감긴 화면 한 줄이 아닌 원본 물리적 한 줄 전체를 선택. 줄 시작에 커서 유지 |
| 5 | 빈 물리적 줄과 개행 없는 마지막 줄의 번호 클릭 | 빈 줄은 그 줄의 실제 개행 선택. 마지막 줄은 본문만 선택하고 개행을 만들지 않음 |
| 6 | 마지막 개행 뒤 커서용 가상 행, 본문 아래 빈 공간, 여백 바깥 클릭 | 원본 번호 없는 공간은 줄 선택 대상으로 받지 않음. 줄 번호 영역을 통한 잘못된 전체 행 선택이 발생하지 않음 |
| 7 | 커서는 다른 줄에 둔 채 원본 4줄 우클릭 | 원본 4줄 전체가 대상 색·윤곽선으로 표시되고 여백 번호가 굵게 표시. 메뉴 제목 ‘작업 대상 · 원본 4줄’과 일치 |
| 8 | 자동 줄바꿈된 긴 줄에서 우클릭 | 같은 물리적 줄의 모든 감긴 영역을 표시. 다른 기록의 본문·다음 물리적 줄은 대상 표시하지 않음 |
| 9 | 문구를 드래그 선택한 뒤 그 문구 안에서 우클릭 → 강조 문구 관리… | 선택 문구를 유지하고 강조 창에도 같은 문구 미리 채움. 대상 표시를 위해 전체 줄 선택으로 바꾸지 않음 |
| 10 | 메뉴를 Esc로 닫거나 닫은 뒤 다른 탭/필터 보기로 이동 | 대상 색·굵은 번호는 해제. 다른 탭의 같은 줄 번호에 표식이 남지 않음. 기존 텍스트 선택은 대상 표시와 별도로 관리 |
| 11 | 분리한 범위 탭에서 표시 줄 번호 클릭·우클릭 | 실제 원본 번호의 해당 범위 안 줄을 선택·표시. 범위 밖 원문을 끼워 넣지 않음 |
| 12 | 다크/라이트 테마에서 대상 행과 A/B·북마크 표식 확인 | 본문 첫 글자와 줄 번호를 읽을 수 있으며 선택 문구·A/B·북마크를 구별. 원문·필터 범위는 유지 |

CRLF/LF/CR 혼합 선택, 가상 행 거절, 여백 좌표와 실제 선택 이벤트 연결, 오래된 메뉴·탭·필터 경계는 비표시 합성 자동 회귀로 확인한다. 아래 기대 결과는 실제 GUI 통과 기록이 아니다.

## 줄 우클릭·세션 분리·간단한 시간 비교 확인

고정 분석 패널은 없다. 로그 줄을 우클릭하면 그 원본 물리적 줄이 작업 대상이 된다. 커서가 이전에 다른 줄에 있었더라도 새로 우클릭한 줄을 사용한다. 시간 값은 그 줄의 소유 헤더에서 읽으며 세션 분리는 물리적 줄 경계를 사용한다.

| 순서 | 조작 | 기대 결과 |
|---:|---|---|
| 1 | analysis-features.log에서 커서를 원본 9줄에 두고 원본 2줄을 우클릭해 시간 기준 지정 | 원본 2줄을 기준으로 사용하고 시간은 소유 헤더 1줄에서 읽음. 9줄이 기준으로 남지 않음. 고정 A/B 분석 패널을 펼치지 않음 |
| 2 | 원본 4줄 우클릭 → 기준과 이 줄 시간 차이 | 간단한 결과 표시줄에 원본 기준 2줄·비교 4줄과 +12ms 표시. 여백의 A/B 표식이 해당 줄을 가리킴. 본문 우클릭 → 시간 비교 결과 → 시간 차이 복사 또는 결과 줄 우클릭으로 복사. ×로 해제 |
| 3 | 결과가 있는 상태에서 원본 7줄의 잘못된 시각을 비교로 시도 | 유효한 시각 없음 안내. 이전 유효한 기준·비교와 결과는 유지하며 잘못된 시각으로 덮지 않음 |
| 4 | 기준을 원본 9줄, 비교를 8줄로 지정 | 원본 헤더 시간 차이를 부호와 함께 표시. 날짜 없는 자정을 임의로 보정하지 않음 |
| 5 | 원본 2줄 우클릭 → 세션 분리 시작, 원본 6줄 우클릭 → 세션 분리 끝 / 새 탭 | 원본 2~6줄, 양 끝을 포함한 5개 물리적 줄을 새 탭으로 표시. 2줄이 본문이어도 헤더 1줄을 자동으로 끼워 넣지 않음. 원본 번호와 개행 유지 |
| 6 | 원본 파일 탭에서 T 3만 표시한 뒤 원본 2줄~6줄을 다시 분리 | 사이의 숨긴 T 7 원본 4줄도 새 탭에 포함. 현재 표시 줄의 복사가 아니라 원본 범위라는 안내 확인 |
| 7 | 끝 줄을 먼저 분리 시작으로 정하고 더 작은 원본 줄에서 분리 끝 실행 | 작은 번호부터 큰 번호까지의 포함 범위로 정리. 같은 줄을 시작·끝으로 정하면 1줄 탭 |
| 8 | 분리 탭에서 필터 전체 선택·내용 필터·전체 원본 검색·주변 보기·기존 필터 복귀 반복 | 어떤 조작도 범위 밖 1줄·7~9줄을 표시하거나 검색하지 않음. 내보내기도 현재 범위 안의 표시 줄만 저장 |
| 9 | 분리 탭에서 Ctrl+G에 원본 1줄 또는 9줄 입력, 범위 안의 4줄 입력 비교 | 밖은 범위 안내 후 거절하고 ‘숨긴 줄 문맥’으로도 밖을 열지 않음. 안의 4줄은 원본 번호로 이동. 필터 숨김이면 범위 내부 주변 보기만 열 수 있음 |
| 10 | 분리 탭 안에서 원본 3~4줄을 다시 분리 | 더 작은 범위의 새 탭을 만들고 부모 탭 유지. 분리 탭의 시작·끝 범위를 벗어나는 새 분리는 거절 |
| 11 | 한 탭에서 분리 시작만 지정하고 다른 탭에서 시간·강조를 설정한 뒤 왕복 | 간단한 분리 시작 표시줄에 원본 번호와 다음 조작 안내. 시작·시간 기준과 결과·강조 규칙은 각 탭에 따로 유지. ×로 시작 해제. 다른 파일의 줄 번호나 결과를 잘못 사용하지 않음 |
| 12 | 한 탭에서 기준/끝 지정 후 파일·필터를 바꾸고 오래된 우클릭 작업을 실행하려는 상황 | 이전 보기의 줄 대상을 사용하지 않음. 재현이 어려운 오래된 메뉴·비동기 경계는 자동 합성 회귀로 확인 |
| 13 | 본문 2줄 우클릭 → 주변 보기, 이후 기존 필터로 복귀 | 클릭한 줄의 소유 기록 중심으로 모든 스레드 앞뒤를 표시. 기준과 실제 건수 안내 유지. 분리 탭에서는 그 범위를 넘지 않음 |
| 14 | 줄 우클릭 → 주변 로그 범위 → 앞뒤 5 / 20 / 100기록. 직접 지정…에서 0·7·10,000 및 잘못된 값 비교 | 앞뒤 각각 지정한 기록 수를 사용. 0은 기준 기록만 표시. 음수·10,000 초과·문자는 거절. 취소는 기존 범위 유지. 파일 끝 또는 분리 범위 끝에서는 실제 표시 건수로 안내하고 밖의 줄은 포함하지 않음 |

부분 기록의 시간은 범위 밖 소유 헤더의 메타데이터를 사용할 수 있지만 실제 표시·검색·내보내기는 범위 안 줄만 사용한다. 현재 실행 중의 별도 보기 탭이며 원본 파일을 변경하지 않는다.

원본 보호 확인에는 샘플의 내보내기 전후 SHA-256 비교를 추가할 수 있다. 실제 사용자 파일 대신 합성 파일로 시험하며, 같은 경로 차단 시험에서 거절이 나와야 정상이다.

## 새로 구현한 높은 우선순위 11개

이 표의 실제 화면 수동 확인은 사용자가 진행한다. 주변 보기·시간은 **로그 줄 우클릭**, 빠른 강조는 **Shift+F8**, 상세 강조 규칙은 **강조 문구 관리… 메뉴**, 필터는 왼쪽 **내용 필터**를 사용한다. 북마크 이름은 왼쪽 북마크 목록의 ‘이름’ 버튼을 사용한다.

| 10 | 설정 저장 | 라이트·20pt·좁은 간격·줄바꿈·패널 폭을 바꾼 뒤 종료·재실행 | 표시 설정 복원. 북마크·검색어·로그 본문은 이 설정 저장 대상이 아님. 저장 실패해도 앱 사용 가능 |
| 11 | 두 기록 시간 차이 | 아래 입력의 원본 1줄 우클릭 기준 지정, 4줄 우클릭 시간 차이. 기준·비교 순서를 반대로 지정. 1·2줄 지정. 잘못된 시간 헤더 선택 | 간단한 결과에 +12ms, 반대로 지정하면 −12ms. 같은 기록의 헤더·본문은 0. 잘못된 시간은 안내하고 이전 유효한 결과 유지 |

숨긴 검색 결과·북마크·시간 위치는 숨김 표시가 있다. 해당 항목을 선택하면 주변 로그가 열리고, 복귀 버튼으로 기존 조건과 위치를 복원한다. 기본 주변 범위는 앞뒤 20기록이며 우클릭 메뉴에서 5/20/100기록 또는 ‘직접 지정…’의 0~10,000기록을 정한다. 분리 탭의 주변 보기·검색·내보내기는 지정 원본 범위로 잘리며 범위 밖 줄은 포함하지 않는다. 본문 우클릭의 시간 결과·이동/북마크·텍스트 동작은 각각 하위 메뉴에 묶여 있다.

검색 선택 범위를 시험할 때 먼저 본문을 선택하고 ‘선택 범위 지정’을 누른다. F3가 만든 새 선택은 이 고정 범위를 바꾸지 않는다. 정규식의 줄별 `^`/`$`는 `(?m)`, 점의 개행 포함은 `(?s)`로 켠다. 0길이 정규식 일치는 목록·caret 이동만 제공한다. CRLF 내부 일치의 결과 오프셋은 정확하게 유지하고, 편집기 선택은 개행 전체로 정규화될 수 있다. 검색 결과·강조는 각 최대 100,000개이며 강조 규칙은 최대 8개다.

## 검색과 필터 및 시간 차이용 합성 입력

아래 내용은 [analysis-features.log](../samples/analysis-features.log)에 저장했다. 파일로 열거나 클립보드에서 새 로그로 열어 사용한다. 각 시간 헤더와 다음 헤더 전의 본문이 한 기록이다. 이 문자열은 직접 만든 합성 자료다.

```text
[014:15:50.113] [T 3] Read start · error ERROR error_code terror · A한🙂 (synthetic.cpp:100)
  timeout · dump=00 01 02 03
  checksum=OK
[014:15:50.125] [T 7] Write complete (synthetic.cpp:200)
[014:15:50.200] [T 3] heartbeat (synthetic.cpp:300)
  timeout
[014:99:00] [T 11] invalid timestamp (synthetic.cpp:400)
[023:59:59] [T 3] before midnight (synthetic.cpp:500)
[000:00:00] [T 7] after midnight (synthetic.cpp:600)
```

- 대소문자 구분을 켜고 단어 검색을 끄면 `error`는 1줄에서 3회 일치한다. 대소문자 구분을 끄면 4회다. 단어 검색을 켜면 구분 켬은 1회, 구분 끔은 2회다. 밑줄을 단어 문자로 보는 상세 설계 기준이다.
- `timeout[\s\S]*checksum`은 첫 기록 안에서 일치한다. 다른 기록의 키워드를 연결한 정규식은 일치하면 안 된다.
- 포함 timeout+checksum의 AND는 원본 1~3줄을 남긴다. OR는 1~3·5~6줄을 남긴다. 제외 heartbeat를 추가하면 5~6줄 기록 전체가 빠진다.
- 원본 1줄과 4줄의 차이는 정확히 12ms다. 기존 multiline-elapsed.log의 원본 3줄과 9줄 차이는 887ms이므로 12ms 시험과 혼동하지 않는다.
- 원본 8줄을 A, 9줄을 B로 지정하면 −23:59:59다. 날짜가 없으므로 자동으로 하루를 더해 +1초라고 표시하면 실패다.

## 구현 단계의 자동 테스트와 성능 확인

수동 확인만으로 다음 항목을 전부 확인하기 어렵다. 해당 경계 조건의 자동 테스트를 추가했고 실제 결과는 검증 기록에 있다.

- 위치 매핑: 필터 뒤 원본 번호, 가상 마지막 행, 숨긴 줄, 빈 문서, 불연속 선택.
- 기록 필터: 헤더·본문·빈 줄 포함, AND/OR·제외 우선, 원본 순서와 혼합 개행.
- 검색: 잘못된 정규식·timeout·0길이 일치·기록 경계·선택 범위 고정·100,000개 제한·최신 결과 게시.
- 강조: 길이가 다른 겹침, 화면 위에서 시작해 현재 화면까지 이어지는 긴 일치, 두 테마 대비.
- 시간: 1 tick·24시간 초과·음수·헤더 소유·최대 범위·탭별 기준 수명.
- 메뉴·탭: 그룹·단축키 표시·설정 동기화·테마, 다중 파일·중복 파일·독립적인 상태와 위치, 닫기·취소 후 이전 비동기 결과가 다른 탭에 게시되지 않는지 확인.
- 줄 작업·범위: 이전 커서와 다른 실제 클릭 줄, 오래된 메뉴 대상 거절, 두 끝·숨긴 중간 줄·혼합 개행·부분 기록·역순·1줄·중첩 범위, 범위 밖 검색/필터/문맥/이동/내보내기 차단.
- 줄 번호 선택·우클릭 대상: 혼합 실제 개행을 포함한 한 물리적 줄 선택, 커서 시작 유지, 필터·분리 범위의 원본 매핑, 빈 줄/마지막 줄/가상 행, 실제 여백 선택 이벤트 연결, 감긴 전체 영역 표식과 메뉴·보기·탭 수명, 기존 선택 문구 유지.
- 다중 행 선택: 정/역방향 범위, Ctrl 드래그 추가/해제의 원래 선택 집합, 자동 스크롤 물리적 끝과 양쪽 endstop, 불연속 복사 객체의 실제 개행, 선택 범위 검색·문자/줄 집계의 간격 보존, 탭·일반 선택·우클릭 복원, 같은 문서의 새 투영 게시 후 오래된 선택 해제.
- 강조 창·시간 결과: 선택 문구 미리 채우기, 규칙 초안의 적용/취소·8개 상한, 기준·비교의 소유 헤더·부호·잘못된 시간 뒤 이전 결과 유지, 탭별 분리 시작·시간·강조 수명.
- 비표시 레이아웃: 범위 탭·검색·분리 시작·시간 결과가 함께 있을 때 본문 높이와 범위를 검사하고 합성 콘텐츠 PNG 생성. 실제 GUI 확인과 구분.
- 붙여넣기·인코딩: 빈/지원하지 않는 자료·클립보드 제공자 예외·긴 로그 다음 짧은 로그, 엄격한 UTF-8/CP949 대체·잘못된 BOM·지원하지 않는 인코딩 거절.
- 저장/내보내기: 설정 충돌·손상/미래 스키마·쓰기 실패·원본 경로/기존 파일 차단·원본 바이트 불변.

필요한 성능 확인은 합성 10/100 MiB를 사용한다. 기존 benchmark.cmd는 local-data의 같은 이름 합성 파일을 교체하므로, 기존 파일을 보호하려면 새 출력 폴더를 지정해 실행한다. 아래 명령은 읽기·투영·AvalonEdit 문서 생성 측정이며 고급 검색/필터의 실측은 검증 기록에 따로 있다.

```powershell
& .\.tools\dotnet\dotnet.exe .\tests\ThreadLogViewer.Tests\bin\Release\net10.0-windows\ThreadLogViewer.Tests.dll --benchmark .\TestResults\my-fresh-benchmark-10 10
& .\.tools\dotnet\dotnet.exe .\tests\ThreadLogViewer.Tests\bin\Release\net10.0-windows\ThreadLogViewer.Tests.dll --benchmark .\TestResults\my-fresh-benchmark-100 100
```

폴더 이름은 아직 존재하지 않는 이름을 사용한다. 검색·필터·결과 목록·선택 집계의 시간과 메모리, 실제 GUI 스크롤/취소 반응을 나누어 측정한다. 콘솔 벤치마크는 GUI 렌더링 성능을 측정하지 않는다. 실행 횟수와 조건을 기록하고 과거 수치를 새 기능의 실측으로 사용하지 않는다.

## 결과 기록 방법

| 구분 | 남길 내용 |
|---|---|
| 빌드 | 실행한 명령, 성공/실패, 경고/오류 |
| 자동 테스트 | 실행 시각·대상 코드, 통과/실패/건너뜀 수, 실패 사례 |
| GUI 확인 | 기능 번호·샘플·조작·기대 결과·실제 결과·통과/실패/미실행 |
| 실측 성능 | 합성 크기·조건·횟수·시간·메모리, GUI/콘솔 구분 |

버전·실행 경로를 함께 기록하면 오래된 배포 파일을 테스트한 결과와 현재 소스 결과를 구분할 수 있다. 기능을 아직 구현하지 않았다면 미실행으로 기록하며 정상 동작으로 추정하지 않는다.
