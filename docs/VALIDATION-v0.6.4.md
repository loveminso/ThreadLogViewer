# v0.6.4 검색 결과 영역 크기 조절 검증 — 2026-10-05

상태: 검색 결과 영역 크기 조절과 접기/펼치기 구현 완료. Release 빌드 경고 0 / 오류 0, 새 집중 회귀 10/10과 전체 회귀 232/232 통과. 합성 콘텐츠 PNG 두 장을 확인했다. 실제 GUI 조작과 성능 측정은 미실행이다.

## 구현 범위

- 본문과 검색 결과 사이 6 DIP 경계선에서 위아래 드래그와 키보드 높이 조절.
- 제목줄 접기/펼치기에서 검색 데이터·강조와 F3/F4 이동 유지. 검색 0건·닫힘·빈 탭에서 패널 및 분할선 행 공간 제거.
- 기존 화면 설정에 패널 전체 선호 높이(헤더·패딩 포함)와 접힘 상태만 추가. 기존 schema 1 설정은 유지하고 새 두 항목이 없으면 기본값으로 읽으며 원본 안전·소유권 검사·저장 위치를 유지.
- 창·상단 보조 영역이 작아지면 표시 높이를 제한하고 다시 넓히면 선호 높이 복원. 본문 120 DIP 확보를 목표로 이용 가능한 공간 안에서 제한.
- Figma 전체 시안 구현이나 새 UI 패키지 도입은 이번 범위에 포함하지 않는다.

## 빌드 및 자동 테스트

기존 프로젝트 내부 SDK·NuGet 캐시로 `build tests/ThreadLogViewer.Tests/ThreadLogViewer.Tests.csproj -c Release --no-restore -m:1 -nr:false`를 실행했다. 최종 빌드 경고 0 / 오류 0이다. 테스트는 빌드 완료 후 `--no-build --no-restore`로 실행하며 로컬 테스트 호스트 연결이 가능한 환경을 사용했다. 외부 네트워크나 실제 창을 사용하지 않았다.

| 항목 | 결과 | 기록 |
|---|---|---|
| 집중 회귀 | 10 통과 / 실패 0 / 건너뜀 0 | [results-layout-focused-final.trx](../TestResults/v0.6.4/results-layout-focused-final.trx) |
| 전체 회귀 | 기존 222개 + 새 10개 = 232 통과 / 실패 0 / 건너뜀 0 | [final-v0.6.4.trx](../TestResults/v0.6.4/final-v0.6.4.trx) |

신규 회귀는 실제 WPF routed 드래그·방향키·버튼 클릭, 높이·접힘 초기 복원, 접기 후 검색 결과/강조/F3 이동 보존, 검색 0건·닫기·탭 전환 행 공간 0, 작은 창·문맥 표시의 일시 제한과 큰 창 복원, 합성 설정 파일의 저장 비활성화·재시작 복원을 검사한다. 드래그 중 예약된 설정 저장과 취소, Esc 취소 후 검색 보존 및 늦은 완료 이벤트도 확인한다. 전체 회귀에는 파싱·원본 줄 매핑·필터·인코딩·원본 안전 내보내기가 포함된다.

초기 작은 창 회귀에서 고정 결과 행이 Grid의 실제 높이를 부풀려 높이 제한을 우회하는 문제를 발견했다. 부모가 배정한 레이아웃 슬롯도 제한에 반영한 뒤 집중 회귀를 통과했다. 독립 검토에서 발견한 드래그 중간값 저장·Esc 검색 닫기는 확정/임시 높이 분리와 드래그 취소 우선 처리로 보완했다. 이전 실패와 빌드 완료 전 실행한 중간 기록은 최종 통과에 포함하지 않는다.

## 합성 콘텐츠 렌더링

96 DPI의 비표시 WPF 콘텐츠를 [다크 1040×600](../TestResults/results-layout/results-dark-small.png)과 [라이트 1360×860](../TestResults/results-layout/results-light-large.png)로 렌더했다. 두 PNG를 직접 읽어 검색 강조·결과 제목/접기 버튼·분할선·결과 목록이 표시되고 본문과 결과 영역이 겹치지 않음을 확인했다. 작은 창은 문맥 안내까지 표시하고, 큰 창은 결과 영역을 확대했다. 두 렌더링은 집중 10개 안에 포함되며 테스트 수에 더하지 않는다.

실제 창·제목줄·팝업·마우스 입력·다른 DPI에서의 동작은 이 이미지로 검증하지 않았다.
