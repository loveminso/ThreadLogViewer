# v0.6.3 새 빈 탭 검증 — 2026-10-03

상태: 새 탭의 `+` 버튼·파일 메뉴·Ctrl+N과 빈 탭의 로그 입력 흐름을 구현했다. Release 빌드 경고 0 / 오류 0, 새 빈 탭 집중 회귀 10/10과 최종 전체 회귀 222/222 통과, 새 self-contained portable 폴더·EXE 파일 버전 0.6.3.0 및 ZIP 510개 파일 전체의 배포 폴더 대비 SHA-256 일치를 확인했다. 실제 프로그램 창·마우스·클립보드는 제어하지 않았다. 이전 [v0.6.2 검증](VALIDATION-v0.6.2.md)의 212개 통과 기록을 보존한다.

## 구현 범위

- 탭줄 오른쪽의 고정 `+`, 파일 → 새 탭, Ctrl+N으로 읽기 전용 빈 입력 탭을 만든다. 처음 실행하거나 마지막 탭을 닫은 뒤에도 `+`가 있다. 빈 탭은 `새 탭 1`, `새 탭 2`처럼 구별하며 닫은 이름 번호를 재사용하지 않는다.
- 빈 탭에는 본문 편집 대신 Ctrl+V 붙여넣기와 Ctrl+O 파일 열기를 안내한다. 로그가 들어오기 전에는 분석·찾기·줄 이동·내보내기를 비활성화한다. 다른 탭의 원본·필터·행 선택·검색·강조·북마크·시간 기준을 유지한다.
- 현재 빈 탭에서 성공한 텍스트 붙여넣기 또는 첫 파일 열기는 그 자리를 채운다. 로그가 있는 탭의 붙여넣기는 새 탭을 연다. 여러 파일은 첫 성공한 파일이 빈 자리를 채우고 이후 파일은 별도 탭으로 연다.
- 열기·붙여넣기 실패는 빈 탭을 보존한다. 이미 열어 둔 파일은 기존 탭으로 이동하며 사용하지 않은 빈 탭도 유지한다. 실제 빈 파일을 연 탭은 파일 경로가 있는 일반 읽기 전용 로그 탭이다.
- 새 탭을 만들면 이전 비동기 읽기와 파일 일괄 열기를 무효화해 늦은 결과가 새 빈 탭을 덮지 못하게 한다.

원본·기존 파일을 덮어쓰지 않고 실행 중 로컬 오프라인 원칙을 유지한다. 합성 자료만 자동 테스트·렌더링·보고서에 사용한다.

배포에는 runtime·라이선스 480개, 합성 샘플 11개, 문서 18개와 README를 포함한다. `user-data`, `local-data`, `TestResults`, Git 자료, 개발 SDK·패키지 캐시를 포함하지 않는다.

## 자동 테스트

| 항목 | 상태 | 결과 |
|---|---|---|
| 최종 새 빈 탭 집중 회귀 | 통과 | 활성 탭 표시 보강 후 10개 통과 / 실패 0 / 건너뜀 0. [new-session-scroll-focused.trx](../TestResults/v0.6.3/new-session-scroll-focused.trx). |
| 최종 전체 회귀 | 통과 | 이전 212개 + 새 빈 탭 10개 = 222개 통과 / 실패 0 / 건너뜀 0. [final-v0.6.3.trx](../TestResults/v0.6.3/final-v0.6.3.trx). |

[NewSessionUxTests.cs](../tests/ThreadLogViewer.Tests/NewSessionUxTests.cs)는 반복 빈 탭 생성·닫기·순환·이름 구분, 다른 탭의 필터와 불연속 행 선택·검색·북마크·시간·강조 보존, 합성 텍스트/파일 입력의 빈 탭 채우기와 일반 탭 새로 열기, 첫 성공 파일 처리·실패 유지·같은 파일 활성화·실제 빈 파일 구별, 늦은 읽기 취소·파일 묶음 버전 무효화·원본 파일 내용 보존을 검사한다.

초기 집중 실행에서 빈 탭 필터 호출 뒤 Ctrl+O 안내가 사라지는 회귀를 발견해 빈 탭 필터 경계와 안내 갱신을 수정했다. 이후 동일 10개가 모두 통과했다. 초기 실패 기록은 수리 이력이며 최종 통과 수에 더하지 않는다.

많은 탭의 첫 합성 이미지에서 새 활성 탭이 가로 화면 밖에 놓이는 것을 발견해 탭 생성·활성화 시 해당 탭을 화면 안으로 가져오게 했다. 기존 레이아웃 회귀 2건에 활성 탭 제목·닫기 버튼이 가로 뷰포트 안에 들어오는 검사를 추가하고 동일 10개를 다시 통과했다.

새 빈 탭 10개는 최종 전체 222개에 포함된다. 집중 실행은 반복 검증 기록이며 전체 통과 수에 더하지 않는다. 이전 212개 회귀를 새 기능에 맞춰 느슨하게 변경하지 않았다.

입력은 합성 `IDataObject`와 프로젝트 내부 합성 파일을 사용한다. 실제 Ctrl+N·Ctrl+V와 시스템 클립보드는 실행하지 않는다. 버튼·메뉴의 이벤트 연결과 단축키 안내를 숨긴 WPF 콘텐츠에서 확인한다.

### 합성 콘텐츠 렌더링

1040×600 다크 및 1360×860 라이트 콘텐츠에 빈 탭 24개를 생성해 가로 스크롤과 고정 `+` 버튼의 위치·겹침·본문 높이 및 활성 탭의 뷰포트 안 표시를 검사했다. [다크 PNG](../TestResults/v0.6.3/new-session-dark.png) · [라이트 PNG](../TestResults/v0.6.3/new-session-light.png)는 비표시 `RenderTargetBitmap` 합성 이미지다. 두 그림을 직접 읽어 24번째 활성 탭 제목·닫기 버튼과 `+`가 겹치지 않고 보이며 빈 입력 안내를 읽을 수 있음을 확인했다.

렌더링 두 건은 집중 10개 안에 포함된다. 실제 창·팝업·제목줄·다른 DPI·키보드 포커스와 네이티브 입력은 검사하지 않았다.

## 실제 GUI 확인

**미실행.** 사용자의 프로그램 제어 금지 지시를 유지한다. 사용자가 [기능 테스트 방법](FEATURE-TEST-GUIDE.md)에서 `+`·Ctrl+N·빈 탭 입력·탭 전환을 합성 샘플로 직접 확인한다. 기대 결과를 실제 GUI 통과로 보고하지 않는다.

## 실측 성능

**미측정.** 탭 생성·파일 열기·붙여넣기·많은 탭 스크롤의 시간과 메모리를 별도 측정하지 않았다. 자동 테스트 실행 시간을 화면 반응 속도로 해석하지 않는다. 이전 버전의 Core·디코딩 측정은 이번 변경의 성능을 대표하지 않는다.
