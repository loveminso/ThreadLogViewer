# ThreadLog Viewer v0.6.4

Windows x64용 SSD 멀티스레드 **읽기 전용** 로그 뷰어. C# + .NET 10 + WPF + AvalonEdit.
실행 중 인터넷, 로그인, API, 서버, DB, 텔레메트리를 사용하지 않습니다.
개발 시 .NET SDK와 NuGet 패키지 다운로드에는 인터넷이 필요합니다. 회사 PC에는 ZIP 전체를 풀어서 복사합니다.

## v0.6.4 — 검색 결과 영역 크기 조절

- 본문과 검색 결과 사이 경계선을 위아래로 드래그해 결과 영역 높이를 바꿉니다. 경계선에 키보드 포커스를 둔 뒤 위·아래 방향키로도 조절합니다.
- 결과 제목줄의 **접기 / 펼치기**는 목록만 접습니다. 검색 강조와 **F3 / F4** 결과 이동을 유지하며, 검색창의 × 또는 Esc로 닫는 동작과 구분합니다.
- 결과 높이와 접힘 상태를 화면 설정에 저장합니다. 작은 창에서는 본문 공간을 확보하도록 표시 높이만 제한하고 창을 넓히면 선택한 높이로 복원합니다.

새 실행 파일은 `artifacts/ThreadLogViewer-v0.6.4-win-x64/ThreadLogViewer.exe`, ZIP은 `artifacts/ThreadLogViewer-v0.6.4-win-x64.zip`입니다. Release 빌드 경고 0 / 오류 0, 새 집중 회귀 **10/10**, 전체 자동 테스트 **232/232 통과**와 다크·라이트 합성 콘텐츠 렌더링을 확인했습니다. 실제 GUI 조작과 성능은 미실행이며 [v0.6.4 검증 기록](docs/VALIDATION-v0.6.4.md)에 구분합니다. 이전 실행 파일과 ZIP을 보존합니다.

## v0.6.3 — 새 빈 탭

- 탭줄 오른쪽의 **+**, **파일 → 새 탭**, **Ctrl+N**으로 `새 탭 1`, `새 탭 2`를 만듭니다. 처음 실행하거나 마지막 탭을 닫은 뒤에도 +를 사용할 수 있습니다.
- 빈 탭은 로그를 넣기 위한 읽기 전용 자리입니다. **Ctrl+V**로 로그를 붙여넣거나 **Ctrl+O**로 파일을 열면 현재 빈 탭을 채웁니다. 로그가 있는 탭에서 붙여넣으면 새 로그 탭을 엽니다.
- 여러 파일을 열 때 첫 성공한 파일이 빈 탭을 채우고 이후 파일은 각각 탭을 엽니다. 실패한 입력은 빈 탭을 유지하며, 이미 열린 파일을 다시 열면 기존 파일 탭으로 이동하고 빈 탭도 남깁니다.
- 새 탭에서도 다른 탭의 필터·불연속 행 선택·검색·강조·북마크·시간 위치를 보관합니다. 빈 탭의 찾기·분석·내보내기는 로그를 넣기 전까지 비활성화합니다. 본문과 원본 파일은 읽기 전용입니다.

## v0.6.2 — 여러 줄 선택과 빠른 문구 강조

- **줄 번호에서 왼쪽 버튼을 누르고 드래그**하면 여러 물리적 줄을 선택합니다. 반대 방향으로 드래그하거나 자동 줄바꿈된 줄을 지나도 같은 원본 줄을 기준으로 처리합니다.
- **Ctrl+줄 번호 클릭 또는 Ctrl+본문 클릭**으로 떨어진 줄을 추가·해제합니다. **Ctrl+C**는 선택한 표시 줄을 원본 순서로 복사하며 실제 CRLF/LF/CR 개행과 마지막 줄의 개행 유무를 유지합니다. 필터로 숨긴 중간 줄과 여백 번호는 복사하지 않습니다.
- **Shift+F8**은 선택 문구 또는 커서 단어의 강조를 즉시 켜고, 같은 문구에 다시 누르면 해제합니다. 새 문구는 아직 쓰지 않은 색을 우선 배정하며 강조 규칙은 탭마다 최대 8개입니다. 색·끄기·삭제를 직접 관리하려면 메뉴의 **강조 문구 관리…**를 사용합니다.
- 행 선택은 탭마다 보관하며 일반 문구 선택·복사도 유지합니다. 본문과 원본 파일은 읽기 전용입니다.

새 로컬 실행 파일은 `artifacts/ThreadLogViewer-v0.6.2-win-x64/ThreadLogViewer.exe`, 생성한 ZIP은 `artifacts/ThreadLogViewer-v0.6.2-win-x64.zip`입니다. Release 빌드 경고 0 / 오류 0, 전체 자동 테스트 **212/212 통과**, ZIP 509개 파일과 배포 폴더의 전체 해시 일치를 확인했습니다. 상세 결과는 [v0.6.2 검증 기록](docs/VALIDATION-v0.6.2.md), 자동 검증 방법은 [TESTING](docs/TESTING.md), 직접 확인 절차는 [기능 테스트 방법](docs/FEATURE-TEST-GUIDE.md)을 따릅니다. 실제 프로그램은 실행·제어하지 않았으며 기존 배포를 보존합니다.

## v0.6.1 — 줄 전체 선택과 우클릭 대상 표시

- **원본 줄 번호를 클릭**하면 그 물리적 줄 전체를 선택합니다. 실제 CRLF/LF/CR 개행이 있으면 함께 선택하며, 개행 없는 마지막 줄에는 개행을 추가하지 않습니다. 자동 줄바꿈된 줄도 원본 한 줄 전체를 선택합니다.
- 선택 뒤 커서는 클릭한 줄의 시작에 유지합니다. Ctrl+F2 북마크나 시간 작업이 다음 줄을 잘못 대상으로 삼지 않습니다. 필터·분리 탭에서도 화면에 표시한 원본 줄만 선택합니다.
- **우클릭 작업 대상**을 행 전체 색·윤곽선과 굵은 원본 줄 번호로 표시합니다. 메뉴의 ‘작업 대상 · 원본 N줄’과 같은 줄을 가리키며 메뉴를 닫거나 보기·탭을 바꾸면 표시를 해제합니다.
- 우클릭 대상 표시는 텍스트 선택과 별개입니다. 이미 선택한 문구 안에서 우클릭해도 선택 문구와 Shift+F8 강조 창의 미리 채우기를 유지합니다. 원본은 읽기 전용입니다.

새 로컬 실행 파일은 `artifacts/ThreadLogViewer-v0.6.1-win-x64/ThreadLogViewer.exe`, 생성한 ZIP은 `artifacts/ThreadLogViewer-v0.6.1-win-x64.zip`입니다. Release 빌드 경고 0 / 오류 0, 전체 자동 테스트 **178/178 통과**, ZIP 507개 파일과 배포 폴더의 전체 해시 일치를 확인했습니다. 상세 결과는 [v0.6.1 검증 기록](docs/VALIDATION-v0.6.1.md), 직접 확인 절차는 [기능 테스트 방법](docs/FEATURE-TEST-GUIDE.md)을 따릅니다. 실제 프로그램은 실행·제어하지 않았으며 기존 배포를 보존합니다.

## v0.6.0 — 로그 줄에서 바로 작업

- 고정 분석 패널을 없애고 **로그 줄 우클릭**으로 주변 보기·시간 비교·세션 분리를 실행합니다. 메뉴의 기준은 이전 커서가 아니라 실제 우클릭한 원본 물리적 줄입니다.
- 시작 줄에서 **세션 분리 시작**, 끝 줄에서 **세션 분리 끝 / 새 탭**을 고르면 두 줄을 포함하는 원본 범위를 새 탭으로 엽니다. 현재 필터가 숨긴 중간 줄도 포함하며 원본 줄 번호·개행을 유지합니다.
- 분리한 탭의 필터·전체 원본 검색·주변 보기·줄 이동·내보내기는 그 범위 안에서만 작동합니다. 다른 범위를 보려면 원래 탭으로 돌아갑니다. 본문은 읽기 전용입니다.
- 우클릭으로 **시간 비교 기준**을 지정한 뒤 비교할 줄에서 **기준과 이 줄 시간 차이**를 실행합니다. 간단한 결과 표시줄에 원본 위치와 비교 − 기준의 부호 있는 시간 차이를 표시하고 여백에 A/B 표식을 보입니다.
- **Shift+F8**로 작은 문구 강조 창을 열고 선택 문구를 미리 채웁니다. 최대 8개 규칙을 관리하며 탭마다 독립적으로 보관합니다.
- 검색은 **F3 다음 / F4 이전**으로 이동합니다. 기존 Shift+F3도 이전 결과의 별칭으로 유지합니다.
- 분리 시작은 간단한 표시줄로 안내합니다. 주변 로그 범위는 우클릭 메뉴에서 앞뒤 **5 / 20 / 100기록** 또는 **직접 지정… (0~10,000)**으로 정합니다. 시간 결과·이동/북마크·텍스트 동작은 하위 메뉴로 묶습니다.

## v0.5.0 — 메뉴와 여러 로그 탭

- 상단을 **파일 / 편집 / 보기 / 분석 / 도움말** 메뉴로 정리하고 각 동작 옆에 단축키를 표시합니다. 화면 설정은 보기 메뉴에서 변경합니다.
- 여러 `.log`·`.txt` 파일을 한 번에 열거나 끌어 놓고, 클립보드 로그도 새 탭으로 엽니다. 탭별 필터·검색 조건·북마크·강조·시간 기준점·주변 보기·현재 위치와 선택을 보관합니다.
- 탭 클릭 또는 **Ctrl+Tab / Ctrl+Shift+Tab**으로 오가고 **Ctrl+W**로 현재 탭을 닫습니다. 같은 파일을 다시 열면 기존 탭으로 이동합니다. 본문은 읽기 전용이며 탭은 현재 실행 중에만 유지됩니다.
- 파일을 열 때 BOM을 확인하고, BOM 없는 입력은 엄격한 UTF-8을 먼저 시도한 뒤 실패하면 엄격한 CP949로 읽습니다. 직접 선택은 **파일 → 인코딩으로 다시 읽기 → 자동 판별 / 한국어 (CP949)**에 있습니다.
- 클립보드 제공자의 읽기 예외를 처리하고, 실패하면 현재 로그를 유지합니다. 이 PC의 v0.4.0 오류 이벤트에서 붙여넣기의 `InvalidDataException`이 처리되지 않아 종료된 사실을 확인하고 예외 경계를 보완했습니다. 빈·지원하지 않는 입력과 긴 로그 다음 짧은 로그 붙여넣기를 회귀 검증했습니다.

- 원본 줄바꿈과 물리적 줄 번호는 유지합니다. 왼쪽은 기록 **건수**, 하단은 **건수와 줄 수**를 표시합니다. 스레드 건수에 마우스를 올리면 해당 스레드의 원본 줄 수도 나옵니다.
- `samples/multiline-elapsed.log`에서 T 1124525만 선택하면 **2건 / 6줄**, 원본 번호 **3, 4, 5, 6, 9, 10**이 남습니다.
- 이전에 중단된 테마·간격·검색·필터·복사·내보내기 GUI 확인을 재개했습니다. 상세 결과는 [v0.3 검증 기록](docs/VALIDATION-v0.3.md)에 있습니다.

## 사용법

1. **+ / 파일 → 새 탭 / Ctrl+N**으로 빈 탭을 만들 수 있습니다. **파일 → 파일 열기** 또는 Ctrl+O로 `.log`, `.txt`를 한 개 이상 선택합니다. 여러 파일을 끌어 놓거나 탐색기에서 복사한 뒤 Ctrl+V로 열 수도 있습니다. 현재 빈 탭은 첫 성공한 파일로 채우고 이후 파일은 각각 탭을 만듭니다. 같은 파일은 기존 탭으로 이동하며 빈 탭은 유지합니다. 폴더는 받지 않고 실패한 입력은 기존 탭을 유지합니다.
2. BOM이 있으면 UTF-8 또는 UTF-16 LE/BE로 읽습니다. BOM 없는 유효 UTF-8은 **추정**이라고 표시합니다. UTF-8에 실패하면 CP949로 대체하며 역시 추정이라고 표시합니다. 글자가 깨지면 **파일 → 인코딩으로 다시 읽기**에서 직접 선택합니다. BOM이 있는 잘못된 입력, UTF-32, UTF-8과 CP949 모두 실패하는 입력은 거절합니다.
3. 스레드 체크박스·전체 선택·전체 해제·‘단독’으로 **기록 전체**를 필터링합니다. 스레드 없는 시간 헤더와 그 본문은 ‘미분류’입니다. 첫 시간 헤더 앞의 스레드 없는 줄도 미분류로 남습니다.
4. 왼쪽의 최초/마지막 기록은 **파일 순서에서 처음/마지막으로 관측된 유효 시각**입니다. 스레드 생성 시각이 아닙니다. 날짜 없는 자정 통과를 임의로 날짜에 배정하지 않습니다.
5. 중앙 여백은 **원본 로그 파일의 줄 번호**입니다. 번호를 클릭하면 실제 개행을 포함한 해당 물리적 줄 전체를 선택합니다. 자동 줄바꿈된 표시 줄도 원본 한 줄로 취급합니다. `(testcase.cpp:103)`의 103은 소스 코드 줄 번호입니다. 여백 번호는 복사·내보내기에 섞이지 않습니다.
6. 줄 번호에서 왼쪽 드래그로 여러 줄을 선택하고 Ctrl+줄 번호/본문 클릭으로 떨어진 줄을 추가·해제합니다. Ctrl+C는 선택한 줄을 원본 순서와 실제 개행으로 복사합니다. 본문의 일반 드래그/Shift+화살표 선택과 Ctrl+A도 유지합니다. 가로·세로 스크롤, 자동 줄바꿈, 글자 크기를 지원합니다. 본문은 읽기 전용입니다. 탭을 클릭하거나 Ctrl+Tab / Ctrl+Shift+Tab으로 파일을 오가면 각 탭의 분석 상태와 위치를 복원합니다. Ctrl+W로 현재 탭을 닫습니다.
7. Ctrl+F로 검색합니다. 대소문자·단어·정규식과 표시 기록/전체 원본/고정 선택 범위를 고릅니다. Enter/F3 다음, Shift+Enter/F4/Shift+F3 이전, Esc 닫기. 검색은 기록 경계를 넘지 않으며 선택 범위는 ‘선택 범위 지정’으로 고정합니다. 분리한 탭의 ‘전체 원본’은 해당 범위 안에서만 검색합니다.
8. ‘필터 결과 내보내기’ 또는 주변 보기의 ‘주변 로그 내보내기’는 **UTF-8 (BOM 없음)** 새 파일을 만듭니다. 원본 경로와 기존 파일의 덮어쓰기를 모두 차단합니다. 기존 파일을 허용하지 않아 원본의 하드 링크·별칭을 통한 덮어쓰기도 방지합니다.
9. Ctrl+G에 원본 줄 번호를 입력합니다. 숨긴 줄은 안내 후 ‘숨긴 줄 문맥’으로 확인합니다. 북마크는 Ctrl+F2로 표시하고 F2/Shift+F2로 이동합니다. 숨긴 검색 결과·북마크·시간 위치를 선택하면 주변 보기를 열며 ‘기존 필터로 돌아가기’로 복귀합니다.
10. 왼쪽 ‘내용 필터’에 한 줄당 한 문구를 입력하고 ‘필터 적용’을 누릅니다. 포함은 ‘하나라도 포함’ 또는 ‘모두 포함’으로 고르고, 제외는 하나라도 맞으면 기록 전체를 숨깁니다. 스레드 조건도 함께 적용됩니다. 입력만 바꾸면 미적용 안내가 표시됩니다.
11. 로그 줄을 **우클릭**해 주변 보기·시간 기준/비교·세션 분리를 실행합니다. 대상 행 전체와 원본 줄 번호를 표시하며 시간은 그 물리적 줄의 소유 헤더를 사용합니다. 메뉴를 닫거나 보기를 바꾸면 대상 표시를 해제합니다. **Shift+F8**은 선택 문구 또는 커서 단어를 즉시 강조·해제합니다. 규칙의 세부 관리는 메뉴의 **강조 문구 관리…**를 사용합니다. 고정 분석 패널은 사용하지 않습니다.

### 원본 범위를 새 탭으로 분리

1. 시작할 줄을 우클릭해 **세션 분리 시작**을 누릅니다.
2. 끝낼 줄을 우클릭해 **세션 분리 끝 / 새 탭**을 누릅니다. 두 끝을 포함하며 반대 순서로 지정하면 작은 원본 번호부터 정리합니다.
3. 새 탭에는 그 사이 **원본 물리적 줄** 전체가 들어갑니다. 필터로 숨긴 중간 줄도 포함합니다. 기록 본문 중간을 끝으로 정하면 해당 기록이 일부만 들어갈 수 있습니다.
4. 분리한 탭에서도 필터·검색·주변 보기·원본 줄 이동·내보내기를 사용합니다. 이 동작으로 범위 밖 원문을 가져오지 않습니다. 분리한 탭 안에서 다시 더 작은 범위를 분리할 수 있습니다.

원본 파일을 복사하거나 변경하는 작업이 아니라 실행 중의 별도 보기 탭입니다. 시작 위치·시간 기준·강조 규칙은 탭마다 따로 보관합니다. 범위 밖 소유 헤더의 시간 정보가 있더라도 표시·검색·내보내기 줄은 지정 범위로 제한합니다.

### 파일 없이 로그 텍스트 붙여넣기

- 다른 프로그램에서 로그 텍스트를 복사한 뒤 로그 화면에서 **Ctrl+V**, **Shift+Insert**, **편집 → 붙여넣기**, **파일 → 클립보드 로그 열기**, 또는 **본문 우클릭 → 텍스트 → 클립보드 로그 열기**를 사용합니다.
- 현재 탭이 **새 빈 탭**이면 붙여넣은 로그로 그 자리를 채웁니다. 로그가 있는 탭에서는 **새 읽기 전용 로그 탭**을 만들고 기존 탭을 유지합니다. 문서에 삽입하거나 원본 파일을 수정하지 않습니다. 이어 붙이기는 지원하지 않습니다.
- 붙여넣은 내용에도 스레드 색상·필터·검색·내보내기가 적용됩니다. 줄 번호는 **붙여넣은 텍스트의 첫 줄부터 1**이며 복사해 온 원본 파일의 줄 번호를 추정하지 않습니다.
- 클립보드는 이미 해석된 Unicode 텍스트이므로 원본 파일 인코딩은 알 수 없다고 표시합니다. **인코딩으로 다시 읽기** 메뉴는 비활성화됩니다. 필요하면 원본 파일을 직접 여세요.
- 검색창의 Ctrl+V는 검색어만 붙여넣습니다. 검색창에 포커스가 있어도 **Ctrl+Shift+V**를 누르면 클립보드를 새 로그로 엽니다.
- 빈 클립보드·텍스트가 아닌 내용·클립보드 제공자 읽기 실패는 상태줄에 안내하고 현재 로그 또는 빈 탭을 유지합니다. 탐색기에서 복사한 여러 `.log`·`.txt` 파일도 첫 성공 입력의 빈 탭 채우기 규칙을 따릅니다. 붙여넣은 로그의 내보내기도 원본과 기존 파일을 덮어쓰지 않습니다.

## 데이터 / 파싱

- `[HH:mm:ss[.소수초]] [T3] 메시지 (소스파일:줄번호)` 또는 `[T 3]`. 시간은 두 자리 이상 (`014`, `025`, `100` 등), 분·초는 00~59, 소수초는 1~7자리까지 해석하며 표시는 입력 그대로입니다. `TimeSpan` 범위를 넘거나 잘못된 시간은 유효 시각으로 표시하지 않습니다.
- 줄의 처음(선행 공백 허용)에 있는 시간 대괄호가 기록 경계입니다. 본문 중간의 시간 문구는 경계가 아닙니다. 다음 헤더가 나올 때까지 실제 개행·빈 줄을 포함한 본문 전체가 같은 기록입니다.
- `[014:99:00]`, `[xx:yy:zz]`처럼 잘못된 값이라도 콜론 두 개가 있는 시간 모양의 선행 대괄호는 새 기록을 시작합니다. 유효 시각은 없다고 처리하고, 명시된 스레드가 없으면 미분류로 분리하여 이전 스레드에 섞이지 않게 합니다.
- 첫 시간 헤더 전에는 각 줄을 별도로 보존하며, 명시적인 `[T3]` 접두어가 있는 줄만 그 스레드에 배정합니다. 시간 헤더 뒤의 `[T3]`는 새 시간 헤더 없이는 본문입니다.
- 누락되거나 잘못된 필드가 있어도 원문과 원본 줄을 보존합니다. 상태줄의 ‘완전’은 시각·스레드·소스 위치가 모두 있는 **기록 헤더**, ‘부분’은 일부만 해석한 헤더, ‘미인식’은 해석하지 못한 기록입니다. 연속 본문 줄은 파싱 실패 건수에 추가하지 않습니다.
- CRLF/LF/CR와 마지막 개행 여부를 원문·내보내기에 보존합니다. 끝 개행 뒤의 편집기 커서용 빈 행은 원본 행 수에 포함하지 않아 여백 번호가 없습니다. 0바이트 파일은 0줄입니다.
- 스레드 색은 ID에 대한 고정 팔레트입니다. 12색 팔레트는 반복될 수 있으므로 번호와 함께 식별합니다.

## 샘플 / 성능

[samples/README.md](samples/README.md)에 합성 샘플을 설명했습니다. `line-mapping.log`에서 T 3만 표시하면 100, 105가 남습니다.

```bat
dotnet run --project tests\ThreadLogViewer.Tests -c Release -- --benchmark TestResults\my-fresh-benchmark-10 10
dotnet run --project tests\ThreadLogViewer.Tests -c Release -- --benchmark TestResults\my-fresh-benchmark-100 100
```

아직 존재하지 않는 출력 폴더 이름을 사용합니다. 벤치마크는 합성 파일을 생성한 뒤 읽기·디코딩·파싱, 필터 투영, AvalonEdit 문서 생성 시간과 해당 콘솔 프로세스 메모리를 JSON으로 저장합니다. UI 배치/렌더 시간은 포함하지 않습니다. 합성 10/100 **MiB**(1 MiB=1,048,576바이트)를 사용합니다.

현재 변경의 검증 결과는 [v0.6.3 검증 기록](docs/VALIDATION-v0.6.3.md)에 있습니다. 이번 새 탭의 성능은 별도 측정 여부를 검증 기록에 표시합니다. 여러 줄 선택·즉시 강조는 [v0.6.2](docs/VALIDATION-v0.6.2.md), 줄 선택·대상 표시는 [v0.6.1](docs/VALIDATION-v0.6.1.md), 줄 작업·범위 탭은 [v0.6.0](docs/VALIDATION-v0.6.0.md)에 보존합니다. [v0.5.0](docs/VALIDATION-v0.5.0.md)은 합성 10 MiB의 **디코딩 단계만** 측정했고 전체 읽기·파싱·탭 전환·GUI 성능을 측정하지 않았습니다. 분석 화면 개선 기록은 [v0.4.1](docs/VALIDATION-v0.4.1.md), 합성 10/100 MiB Core 실측은 [v0.4](docs/VALIDATION-v0.4.md), 과거 전체 투영/AvalonEdit 문서·GUI 확인은 [v0.3](docs/VALIDATION-v0.3.md), [v0.2](docs/VALIDATION-v0.2.md), [v0.1](docs/VALIDATION.md)에 보존합니다. 측정 범위가 달라 과거 수치와 직접 비교하지 않습니다.

## 구조와 현재 한계

- `src/ThreadLogViewer.Core`: UI와 독립적인 읽기, 인코딩, 파싱, 줄 매핑, 필터, 검색, 원본 보호 내보내기.
- `src/ThreadLogViewer.App`: WPF 화면과 AvalonEdit 렌더링. 화면에 보이는 줄만 그립니다.
- `tests/ThreadLogViewer.Tests`: xUnit 자동 테스트와 재현 가능한 벤치마크.
- 열린 탭마다 메모리에 디코딩 원문·행 정보·표시 문서를 유지합니다. 탭을 많이 열면 메모리 사용량이 늘어납니다. 2GB 이상 파일은 차단하며 그 미만도 RAM과 줄 길이에 따라 한계가 있습니다. 극단적으로 긴 한 줄은 표시가 느려질 수 있습니다.
- 전체 디코딩 및 AvalonEdit 문서 생성의 내부 단계는 즉시 취소되지 않을 수 있습니다. 백그라운드에서 끝난 뒤 취소를 확인하며 UI는 계속 조작할 수 있습니다.
- 검색은 첫 100,000개까지 강조·이동하며 초과 여부를 표시합니다. 닫기로 검색을 취소할 수 있습니다. 필터 변경은 검색을 다시 수행합니다.
- 글꼴 폴백의 한글 폭은 설치 글꼴에 영향을 받습니다.
- 실시간 파일 추적·편집·타임라인·북마크 영구 저장·단축키 사용자 지정은 후속 기능입니다. [계획](docs/PLAN.md) 참고.
- 기능 추가 검토: [37개 후보 전체 표](docs/FEATURE-CANDIDATES.md), [높은 우선순위 11개 상세 설계 및 구현 상태](docs/HIGH-PRIORITY-FEATURES.md). 1~11번은 v0.4, 28번 다중 파일 탭은 v0.5에 구현했습니다. 22번 인코딩 선택은 자동/CP949 메뉴 범위를 반영했으며 UTF-8/UTF-16 수동 선택은 후속 후보입니다.
- 공개 저장소에는 소스·문서·합성 샘플만 포함합니다. 실제 로그는 버전 관리에서 제외한 `local-data/`에 보관하고 공개 저장소나 릴리스에 올리지 마세요.
